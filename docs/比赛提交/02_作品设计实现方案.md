## 1. 项目概述

### 1.1 赛题背景与痛点

大模型为教育内容的按需生成提供了可能，但在垂直领域技能培训中存在三个突出问题：

| 痛点 | 表现 | 本作品对策 |
|:--|:--|:--|
| **幻觉** | 生成专业实操指南时输出不符合行业规范的内容，在教育培训中不可接受 | 知识图谱事实锚定 + 生成-审核-打回博弈 + 独立裁判双口径质检 |
| **个性化与专业性难调和** | 放开限制迁就学情则失准，守住专业性则失去个性 | 画像驱动难度自适应与图谱事实约束**解耦分层**：风格适配让位于事实底线 |
| **千人一面** | 静态资源分发无法匹配差异化学习者 | 画像（学历背景/理论水平/VARK 风格/学时节奏）驱动的路径与资源双个性化 |

### 1.2 目标与定位

面向 **Python 编程垂直领域**的技能培训，构建覆盖两类场景的完整闭环系统：

- **场景一 · 无项目技能训练**：学情画像构建 → 多智能体协同调度（诊断/生成/审核）→ 领域知识个性化生成 → 交互反馈 → 动态决策更新；
- **场景二 · 有项目二次开发**：真实代码项目自动解析为**项目代码图谱**，代码审查/代码测试双 Agent 协同给出架构解读与质量反馈，薄弱点反向沉淀入学习路径。

产品以 **Electron + Monaco 桌面 IDE** 形态交付，端用户**免 Docker、免命令行、免改配置文件**。

### 1.3 核心创新点

1. **四层知识图谱作为多 Agent 共享事实底座**——领域元知识 → 项目框架 → 代码实体 → 演化扩展，292 个元知识节点 + 423 题的知识库切片随包分发，所有 Agent 的输入输出均锚定图谱节点，从源头约束生成边界；
2. **「辩论与交叉验证」抗幻觉机制**——内容审核 Agent 对照图谱事实逐条校验生成内容（含溯源校验：引用了不存在节点即打回），不合格定向打回并注入修正提示再生，多轮博弈直至通过或上限终止；
3. **独立裁判（LLM-as-Judge）双口径质检**——生成质量不由"作者自批"，由可异源配置的独立裁判模型逐资源判定幻觉/难度，幻觉率 2.4%、适配率 94.0%、覆盖率 100%（赛题达标线 <5% / ≥85% / ≥90%），并以 12 例黄金回归集钉住裁判行为；
4. **画像驱动的三形态资源生成**——同一知识节点按学习者画像生成分层讲义 / 阶梯式实操指南 / 分阶测试题三种形态，难度与措辞随 `adaptation_profile`（beginner/intermediate/advanced）自适应，每段内容标注 `source_nodes` 可溯源；
5. **端用户零门槛的工程化交付**——安装包内置 PyInstaller 打包的后端 sidecar 与进程内嵌入式图存储（Neo4j 仅为可选），单文件安装即用。

### 2.1 三层架构总览

```

               │ Electron IPC（HTTP 代理 + SSE 流式，主进程转发）
┌──────────────┴─────────────────────────────────────────────┐

│  主控调度 Agent —— LangGraph StateGraph 全流程编排           │

│    ＋ 独立裁判(LLM-as-Judge)  ＋ 动态建域 Agent(未收录领域)   │

│  数据层：四层知识图谱（12 文件 / 292 节点 / 12 分类 + 423 题） │
```

### 2.2 四层知识图谱设计

| 层 | 内容 | 规模 |
|:--|:--|:--|
| L1 领域元知识 | Python 92 节点（基础语法/数据结构/面向对象/进阶/常用库/项目实战）+ 机器学习 30 + 数据分析/Web 后端/数据库与缓存/工程化各 25 + 动态领域 70（Java/CS/AI 等 7 个迷你域各 10） | 12 文件 292 节点，节点含难度/前置依赖/要点/常见误区/内嵌练习 |
| L2 项目框架 | 示例与用户项目的框架级抽象 | `simple_crawler`、`todo_backend` 两个示例项目 |
| L3 代码实体 | 函数/类/调用/包含/继承关系（AST + Jedi 解析） | >150 实体大项目自动模块聚合 |
| L4 演化扩展 | 掌握状态/风险标注/动态建域产物 | 运行时写入，画像跨次进化档案 |

节点字段遵循 `data/knowledge_base/nodes/schema.json`（JSON Schema 约束），题库 163 文件 423 题（choice/fill/judge/code 四型）按节点挂载。

### 2.3 进程拓扑

- **渲染进程**（Vue3 + Element Plus + AntV G6）：IDE 壳、学习会话、图谱可视化、AI 助手；
- **Electron 主进程**：窗口管理、文件系统/工作区 IPC、HTTP 代理（渲染进程不直连后端，天然适配打包形态）、代理配置落盘、sidecar 生命周期；
- **后端 sidecar**（PyInstaller 单文件）：FastAPI REST + SSE，LangGraph 编排，OpenAI 兼容 LLM 接入（默认 DeepSeek V4 Pro，反馈通道可用快模型 deepseek-v4-flash 分流，千问 1536 维 embedding 语义检索）；
- **图存储**：默认进程内 `EmbeddedGraphStore`（JSON 真相源 + 本地可变数据目录，查询零网络往返，BFS 等价变长 Cypher）；可选 Neo4j 5.x（Docker，多端共享场景）。

## 3. 多智能体协同机制（对应赛题要求(2)(4)①）

### 3.1 角色分工：7 个核心 Agent + 2 个辅助 Agent

| Agent | 职责 | 关键实现 |
|:--|:--|:--|
| **主控调度**（orchestrator） | LangGraph StateGraph 编排全流程，路由决策（通过/打回/降级终止） | `backend/app/agents/orchestrator.py` |
| **学情检测**（diagnostics） | 题库驱动出题→判分→三维能力画像（理论水平 × VARK 学习风格 × 实操倾向），采集学时节奏 | `diagnostics.py` |
| **图谱管控**（graph_controller） | 依据画像从图谱组装个性化学习路径（依赖拓扑 + 掌握度加权 + 上限裁剪），状态写回 | `graph_controller.py` |
| **内容生成**（content_generator） | 对路径节点并发生成三形态资源，附 `source_nodes` 溯源标记 | `content_generator.py` |
| **内容审核**（reviewer） | 画像/内容双模式审核：四维加权评分（准确性/难度/结构/安全）+ **溯源逐条校验** | `reviewer.py` |
| **代码审查**（code_reviewer） | 场景二：对照领域规范审查项目代码 | `code_reviewer.py` |
| **代码测试**（code_tester） | 场景二：生成 pytest 用例并在沙箱执行，风险节点反向标注图谱 | `code_tester.py` |
| 独立裁判（quality_judge） | LLM-as-Judge 逐资源幻觉/难度判定，可与生成模型异源 | `quality_judge.py` |
| 动态建域（domain_bootstrap） | 未收录领域当场联网构建迷你域（70 节点即其产物入库） | `domain_bootstrap.py` |

系统提示词 11 个文件（`data/prompts/`：00 共享契约 + 01–08 主链 8 套 + 独立裁判 2），提示词契约由 `test_prompt_contract.py` 钉住防漂移。

### 3.2 「分析—生成—校验—决策」协同闭环

场景一的固化流程拓扑（`workflow_def` 内置定义，随 run 快照落盘可复盘）：

```
diagnostics（学情检测）→ review-profile（画像审核）→ graph（图谱组装）
      → content（内容生成）→ review-content（内容审核）─┬─ 通过 → 交付
                                                        └─ 不合格 → 打回 content 定向再生（带上轮审核意见）
```

- **调度可视化**：每个阶段的结构化事件（agent-start/agent-end/error，含耗时与进度消息）经 `log_events` 落盘 `data/workflow_runs/<sid>/events.jsonl`，前端学习会话「协同」阶段与流程 DAG 实时渲染各 Agent 状态；
- **逻辑门决策**（`evaluate_gate`）：流程编排中的分叉不写死在代码里，而由流程定义的谓词决策（如反馈策略 advance/remediate/scaffold 的阈值判定与 `decide_feedback` 对齐，`test_workflow_def.py::test_strategy_decision_matches_decide_feedback_thresholds` 钉住两者一致）；
- **耐久运行档案**（`run_store`）：每次运行的请求/流程快照/事件流/摘要原子落盘，支持复盘、按此重跑、一键续跑；
- **优雅降级**：LLM 不可用时流程标记 `degraded` 并跳过可缺省节点（前端可视化降级状态），不产生半成品缓存。

### 3.3 辩论与交叉验证抗幻觉

1. **事实锚定**：生成 prompt 强制只允许使用图谱节点事实（summary/key_points/common_mistakes），禁止编造图谱外知识；
2. **溯源校验**：审核 Agent 对每条资源的 `source_nodes` 逐条核对——引用了不存在的节点、或内容与节点事实不符即判幻觉并打回；
3. **定向再生**：打回时将审核意见注入 `correction_hint`，只重新生成被点名的内容（节点级再生缓存，15 次调用可降至 3–6 次），多轮博弈直至通过或达重试上限强制终止；
4. **独立裁判复核**：通过初审的资源再由独立裁判逐条判定 `grounded / hallucinated / unverifiable`，`unverifiable` 不计入幻觉率分子但如实披露；裁判模型支持 `JUDGE_LLM_*` 异源配置，避免"生成器自批"；
5. **幻觉定向再生脚本**（`quality_regen.py`）：批跑后对 flagged 资源原位替换，形成离线质检闭环。

### 3.4 知识溯源约束生成

每条生成资源的 `source_nodes` 字段记录其引用的图谱节点 ID 及具体字段（如 `PY-009.key_points[0..5]`）。前端点击资源段落可高亮其溯源节点——**每一段教学内容都能回答"这个知识点从哪来"**。

## 4. 知识图谱引擎（对应赛题要求(2) 知识库整合）

- **混合检索**：Cypher/BFS 图遍历（结构相似）+ 原生向量索引（cosine，1536 维，语义相似）双路召回；未配置 embedding 时自动降级名称匹配并在界面明示（不静默失败）；
- **学习路径组装**：画像 known/weak 节点集 → 前置依赖闭包 → BFS 最短路径 → 掌握度加权排序 → `max_nodes` 上限裁剪（默认 12）→ 按每周可学时长折算「预计 N 周」；
- **嵌入式免 Docker 存储**（`embedded.py`）：以知识库 JSON 为真相源，可变数据（项目图谱/掌握状态/向量缓存）落本地用户目录；离线向量种子随包分发（`export_embeddings.py` 可再生），语义检索就绪前守卫降级纯图模式；
- **一致性保障**：`test_engine_parity.py` 对同一数据集跑 Neo4j 与嵌入式双实现断言等价，嵌入式存储 17 项单测覆盖遍历/批量前置/向量降级。

## 5. 个性化资源生成（对应赛题要求(2) 至少 3 种形态）

### 5.1 三形态资源

| 形态 | 内容 | 判定 |
|:--|:--|:--|
| `lecture` 分层讲义 | 学习目标/知识讲解/常见误区，按画像措辞 | 零基础版 vs 进阶版同一节点措辞梯度显著 |
| `practice_guide` 阶梯式实操指南 | 真实任务背景 + 5 级脚手架渐进揭示 | 任务背景随画像背景变化（学生 → 开发者项目） |
| `test` 分阶测试题 | 基础 50% + 进阶 50%，格式冻结可在本地作答判分 | 难度分布随 `theory_level` 调整 |

### 5.2 画像驱动的难度自适应

画像信号（学历背景/编程经验/理论水平/VARK 风格/学时节奏）注入生成 prompt 与审核维度：`adaptation_profile ∈ {beginner, intermediate, advanced}` 与 `theory_level` 共同决定资源难度档与措辞风格。实测同一节点（如 PY-009 列表）对零基础画像生成 beginner 入门版、对有经验画像生成 advanced 进阶解读版。

### 5.3 文风契约

v1.3.3 起文风契约入共享协约：禁"首先/总之"模板腔、列表 ≤6 条、禁 emoji 排版、`[ref:]` 等机器标记不得泄漏进正文（提示词禁止 + 渲染层兜底剥离）——保证生成资源"排版规范、展示清晰"（对应评分-用户体验）。

## 6. 动态反馈与启发式导学（对应赛题要求(3)②(4)②）

- **三策略动态决策**：按答题正确率，多智能体协同决策下一动作——≥80% `advance`（进阶挑战）/ 50–79% `remediate`（降维解释）/ <50% `scaffold`（补前置脚手架）；策略阈值与流程逻辑门同源；
- **苏格拉底式导学**：AI 助手导学模式以引导追问替代直接给答案，支持动态追问；
- **三阶段交互测评**：idle → answering → feedback，SSE 流式推进度（判分 → 画像 → 路径组装逐段可见），支持停止等待/重试（后台结果入缓存）；
- **画像跨次进化**：稳定 learner 档案 + 掌握度加权合并 + 版本 diff 展示"本次变化" + 30 天未重测遗忘降级提醒；
- **薄弱点联网补强**：Tavily 检索外部资源补充薄弱主题，生成失败透明可重试。

## 7. 可视化报告（对应赛题要求(3)①）

- **知识盲区定位**：图谱节点掌握度着色 + 弱项清单（含错题模式 `error_patterns`）；
- **资源难度匹配曲线**：生成资源难度 vs 画像理论水平逐点对比（85/85 条资源难度匹配实测达标）；
- **学习路径规划图**：BFS 路径 chip（颜色=难度色）+ 一键在图中高亮；
- **数据看板**：学情雷达图（三维画像）、掌握度分布、趋势图；M5 三指标（幻觉率/适配率/覆盖率）随报告呈现；
- 所有图表数据来自真实运行落盘的 `learning_report` 与 run 档案，非伪造展示数据。

## 8. 质量检测体系（对应评分-实用价值 30 分）

### 8.1 三指标定义与实测（10 组差异化画像 × 83 条资源）

| 指标 | 定义 | 赛题达标线 | 自评口径 | **独立裁判口径** |
|:--|:--|:--:|:--:|:--:|
| 幻觉率 | 判定 hallucinated 的资源占比 | <5% | 10.0% | **2.4%**（2/83） |
| 适配率 | 难度与画像匹配的资源占比 | ≥85% | 100% | **94.0%**（78/83） |
| 覆盖率 | 被资源覆盖的弱项节点占比 | ≥90% | 100% | **100%**（33/33） |

裁判源为独立 LLM（未配 `JUDGE_LLM_*` 时回退主模型并在报告标注 same_source，如实披露）。报告由 `backend/scripts/run_quality_test.py` 自动生成（`docs/质量与验收/质量检测报告.md`），含逐条资源的判定证据链。

### 8.2 黄金回归集

`backend/tests/fixtures/judge_goldens.json` 固化 12 例（幻觉 8 + 难度 4，取材真实错误族）：离线假模型跑断言（`test_judge_goldens.py`），真模型 live 复核（`run_judge_golden.py`），防止裁判 prompt 改动引入行为漂移。

## 9. 两类场景全流程

### 9.1 场景一 · 无项目技能训练（主线闭环）

学习会话四阶段卡：**目标**（选择/输入方向，未收录领域触发动态建域）→ **答题**（题库+LLM 补题，四型题目）→ **协同**（多 Agent 调度可视化 + SSE 分步进度）→ **图谱**（路径图 + 三形态资源交付 + 动态反馈迭代）。

### 9.2 场景二 · 有项目二次开发

打开 Python 项目 → 后台 AST/Jedi 解析生成项目代码图谱（重启恢复 + 过期检测：源文件改动后横幅提示并禁用过期跳转）→ LLM 架构解读 + 技术栈检测 → 代码审查四维报告 + 沙箱 pytest 测试 → 风险节点反向标注图谱 → Monaco 符号联动跳源码。LangGraph 流程编排（`project_workflow`）使解析→审查→测试按图执行、状态可观测。

## 10. 桌面 IDE 形态

- **AI 助手**：多厂商 OpenAI 兼容接入，SSE 流式 + 13 工具调用循环（只读工具结果自动回喂）+ `write_file` 审批门 + 消息分支 + 对话持久化；导学模式；流式指标（首 token 延迟/tok·s⁻¹）；

- **代码测试沙箱**：subprocess（环境变量白名单，密钥不外泄）与 Docker 双模式可切换；
- **Git 面板**：克隆/初始化/状态/提交/拉取/推送（`execFile` 无 shell 注入，不保存凭据）；
- **运行历史**：run 档案列表 + 事件时间线 + 按此重跑；
- **安全加固**：Electron sandbox/CSP、文件写联邦守卫、交互日志脱敏组件（`PRIVACY_REDACT_INTERACTION_LOGS`）。

## 13. 创新点总结与展望

**总结**：以四层知识图谱为共享事实底座、LangGraph 多智能体协同为核心引擎，通过"事实锚定 → 溯源校验 → 博弈再生 → 独立裁判"四道防线把大模型幻觉率压到 2.4%，同时以画像自适应保住个性化体验；工程上以嵌入式存储 + sidecar 打包实现端用户零门槛部署。

**展望**：① 领域泛化——动态建域已支持未收录领域当场构建，后续扩展行业规范库接入；② 多 Agent 协同可视化深化——流程工作台（可编辑流程）已具备事务与回滚基础；③ 终身学习档案——画像跨次进化档案向学习经历链上存证延伸。
