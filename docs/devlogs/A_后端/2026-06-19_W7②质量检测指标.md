## 二、指标定义（与赛题 9.2 评分标准 / M5 检查点对齐）

| 指标 | 定义 | 数据源 | 达标线 |
|:---|:---|:---|:---:|
| 幻觉率 | 1 − avg(factual_accuracy.score, hallucination.score)；reviewer 抗幻觉维度补数。reviewer 通过(满分)→0% | `review_results.dimensions` | <5% |
| 适配率 | 难度匹配资源(\|gap\|≤1) / 总资源 | `learning_report.difficulty_match.summary` | ≥85% |
| 覆盖率 | 学习路径覆盖的弱项节点 / 弱项节点总数；无弱项→1.0 | `profile.weak_topics` ∩ `knowledge_graph.learning_path` | ≥90% |

幻觉率取 reviewer 两个抗幻觉维度（factual_accuracy + hallucination）分数的补数：reviewer 打回即扣分 → 幻觉率上升；reviewer 一次过(满分)→0%。这把赛题(4)①抗幻觉博弈的**结果**量化成了可展示数字。

## 三、实现

### `backend/app/agents/quality_metrics.py`（新，纯函数）
- `compute_hallucination_rate(review_results)` — 维度补数 + issue 计数 + flagged 标志
- `compute_adaptation_rate(difficulty_match)` — matched/total
- `compute_coverage_rate(profile, knowledge_graph)` — 弱项∩路径 / 弱项
- `compute_quality_metrics(...)` — 组装三项 + targets + all_passed 判定
- 常量 `HALLUCINATION_TARGET=0.05 / ADAPTATION_TARGET=0.85 / COVERAGE_TARGET=0.90`
- 纯函数，不调 LLM，维度缺失防御性默认 1.0（无幻觉检出）

### 集成到 `report_builder.build_learning_report`
- 复用已算好的 `difficulty_match` 子对象（传 `learning_report={"difficulty_match": dm}`），避免重算
- `learning_report` 新增 `quality_metrics` 子对象 → **per-session 实时指标**
- demo 模式 assess 一次返回 + interactive 模式 /api/learning/report 补跑，均携带质量指标
- 评委演示时 Dashboard 可直接读 `learning_report.quality_metrics` 显示"幻觉率0% / 适配率100% / 覆盖率100%"

### `backend/scripts/run_quality_test.py`（新，批量脚本，M5 交付物）
- 跑 3 内置画像（beginner/intermediate/advanced）通过完整工作流（demo 模式 LLM 自动作答）
- 每画像算 quality_metrics，聚合（加权）：
  - 幻觉率(批量) = 检出幻觉运行数 / 总运行数
  - 适配率(批量) = 总 matched / 总资源
  - 覆盖率(批量) = 总 covered / 总弱项
- 产出 `data/quality_report.json`（机读）+ `docs/质量与验收/质量检测报告.md`（人读，M5 交付物）
- 含指标总览表 + 逐画像明细 + 抗幻觉机制说明
- 用法：`python scripts/run_quality_test.py [--profiles ...] [--out ...]`

### 单测 `backend/tests/test_quality_metrics.py`（新，18 例）
- 幻觉率：满分→0、低分→补数、维度缺失→0、空 review→0
- 适配率：全匹配、部分、无资源→0、达标边界
- 覆盖率：全覆盖、部分、无弱项→1.0、达标边界
- 组装：全达标、单项失败(幻觉/适配/覆盖各一)、兜底现算 difficulty_match、generated_at

## 四、根因调查与修复（系统调试法）

首轮测试的价值正在于暴露真实弱点。三项指标中幻觉率 0% 已达标（抗幻觉博弈有效），但适配率/覆盖率不达标。按"先查根因再改"逐项诊断：

### BUG-042：覆盖率根因 — assemble_learning_path 只插弱项前置、漏弱项本身

**症状**：3 个差异极大的路径（4/12/12 节点）覆盖率全是精确 33.3%（1/3），跨规模一致性暗示非真实覆盖缺口。

**根因**：`engine.assemble_learning_path` 注释称"弱项前置依赖链优先插入"，但 F8 patch 代码只 `get_prerequisites(wid)` 插入**前置依赖**，从不把**弱项节点本身**纳入路径。弱项节点除非恰好落在 BFS 扩散（known 后继）范围内，否则不入路径 → 3 弱项仅 1 个命中 → 1/3。

**修复**：在 F8 patch 之后追加弱项节点本身（前置先入、弱项紧随），受 `difficulty_cap` 保护（零基础 level=1 不直推难度4-5弱项避免挫败，其前置已先入路径）。去重（known_set/path_ids）。

**验证**：`test_engine_learning_path.py` 6 例（弱项入路径/前置先于弱项/超cap跳过/多弱项全入/known去重）+ 真实集成覆盖率 33.3%→100%。

### BUG-043：适配率根因 — LLM 自填 difficulty_level 覆盖节点难度

**症状**：适配率 51.9%，资源难度与节点难度 |gap|>1 偏多。

**根因**：`_build_generation_prompt` 让 LLM 输出 `"difficulty_level": 1-5`，`_generate_one` 用 `setdefault` —— LLM 自填值（讲义倾向填偏高）覆盖节点难度，导致 gap 错位。难度本应由图谱事实决定（"组装而非生成"理念），非 LLM 臆造。

**修复**：① prompt 去掉 difficulty_level 字段、注明"由系统统一赋值"；② `_generate_one` 把 `setdefault` 改为**强制赋值** `data["difficulty_level"] = node.difficulty`，LLM 若仍返回也覆盖。资源难度严格对齐节点 → gap=0。

**验证**：`test_content_generator_unit.py` +2 例（强制覆盖/节点无难度兜底）+ 真实集成适配率 51.9%→100%。

### 修复前后对比（真实集成，3 画像）

| 指标 | 修复前 | 修复后 | 达标线 |
|:---|:---:|:---:|:---:|
| 幻觉率 | 0.0% | 0.0% | <5% ✅ |
| 适配率 | 51.9% | 100.0% | ≥85% ✅ |
| 覆盖率 | 33.3% | 100.0% | ≥90% ✅ |

3 画像（零基础/爬虫/后端进阶）全达标，reviewer 审核 0.96-1.0 一次过。**两项修复经真实集成验证生效，非改指标定义凑数。**
