## 三、关键设计决策

### 1. F1 embedding 接入用 `create_embedding_client` 的探测机制

`create_embedding_client()` 内部已做 endpoint 可用性探测（`engine.py:64-71`），失败返回 None。lifespan 直接调用它，探测失败时 `kg.embedding_client=None` → 语义检索自动降级纯图模式，与现有降级逻辑无缝衔接，不引入新分支。

### 2. F2 `_normalize_dims` 写成对异常结构免疫的纯函数

LLM 输出方差是现实问题（DeepSeek 常简化 schema）。`_normalize_dims` 把任意输入规整为 `{dim:{score:float,issues:list}}`：非 dict→默认满分、扁平数字→包成 {score}、缺字段→补默认、非 number→1.0。归一化后 `_merge_issues`/`_weighted_score` 用 `.get` 防御，彻底消除结构崩溃路径。可独立单测（+6 用例）。

### 3. F5 node_id 反查优先级

`question_index`（BUG-022 治本已加兜底）比 grade 的 `node_id` 二次回传可靠——题目 node_id 是出题时服务端持有的真实值。故 `nid = questions[q_idx].node_id`，仅反查失败才 fallback 到 `g.get("node_id")`。治本但保留兜底，不破坏现有 `_grade` 单测。

### 4. F3 level 过滤用 `level+2` 而非 `level`

`level` 是当前水平，路径应允许适度进阶。`level+2`（零基础 level=1 → 上限难度 3）平衡"不推远超水平节点"与"允许进阶"。clamp 到 [1,5]。
