## 三、工作流变化

旧 W3：

```
diagnostics → reviewer(审画像) → graph_controller → finish
```

新 W4：

```
diagnostics → reviewer(画像模式)
  ├─ 通过 → graph_controller → content_generator → reviewer(内容模式)
  │                                           ├─ 通过 → finish
  │                                           ├─ 不通过&未超限 → content_generator
  │                                           └─ 超限 → finish(待人工审核)
  ├─ 不通过&未超限 → diagnostics
  └─ 超限 → finish(待人工审核)
```

reviewer 通过 `_in_content_phase(state)` 判断审核对象：
- 无 `generated_content.resources` → 画像模式
- 有非空 resources → 内容模式

## 四、生成内容契约

`generated_content`：

```json
{
  "resources": [
    {
      "content_type": "lecture|practice_guide|test",
      "target_node_id": "PY-005",
      "difficulty_level": 2,
      "adaptation_profile": "beginner|intermediate|advanced",
      "source_nodes": ["PY-005.key_points[0]", "PY-005.summary"],
      "content": "markdown正文...",
      "generated_at": "2026-06-18T...Z"
    }
  ],
  "node_count": 3,
  "content_types": ["lecture", "practice_guide", "test"],
  "generated_at": "2026-06-18T...Z"
}
```

控量策略：默认对学习路径前 3 个节点生成，每节点 3 段资源，共最多 9 段。避免全路径 LLM 调用过久。`MAX_NODES_TO_GENERATE=3` 可调。

---

## 五、关键设计决策

1. **reviewer 双模式而非新增 reviewer 节点**：保持 LangGraph 简洁，并真正解决 BUG-016（prompt 设计审内容、旧代码审画像）。同一个 reviewer 根据 state 自动判断审核对象。
2. **内容审核硬规则先校验溯源**：`source_nodes` 格式合法 + 节点真实存在是内容可信的最低门槛；复杂事实一致性交 LLM 语义审核。
3. **非法 JSON 降级补全**：`parse_llm_json` 对非法文本返回 `{}`；`_generate_one` 用 `setdefault` 补全结构，避免 LLM 偶发格式错误中断整个流程。
4. **生成失败局部容错**：单段资源生成异常只跳过该段并计 failures，不中断其他节点/资源生成。
