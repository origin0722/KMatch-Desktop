# 动态建域 — 领域未收录时 LLM 当场构建知识图谱（阶段16）

> 2026-08-14 · 后端为主（agents/domain_bootstrap + api/diagnostics 接线）+ 前端三处小改
> 关联: 总览阶段16 / data/prompts/08_domain_bootstrap_agent.txt / schema.json 扩字段

## 背景与问题

用户问"想学的领域知识库没有怎么办，能当场生成题目吗"。调查发现两层问题：

1. **静默错域（bug 级）**：`target_direction` 传进 `_fetch_candidate_nodes` 后函数体
   完全没用它（diagnostics.py:39-53）——用户想学 Java，零基础分支拿到的是
   "全库难度 1-2 前 8 个节点"（基本是 PY 基础），不报错不提示。
2. **无"无中生有"路径**：LLM 补题（`_generate_supplement`）、练习题生成
   （content_generator test 资源）、审核打回（reviewer）、KB 落库通道全部现成，
   但全部锚定既有图谱节点；content_generator 的提示词还明令禁图谱外事实。

## 方案（与用户对齐三决策）

- **动态建域落库**（vs 会话级临时出题）：LLM 生成迷你域（10 节点 + 前置 DAG +
  每节点 2 题）走现有 KB CRUD 通道入库，全链路自动复用，二次学习同域还能命中复用
- **Tavily 联网增强**（vs 纯 LLM）：建域前搜"学习路线/核心概念"作事实锚，
  失败静默降级
- **入主库 + 打标**（vs 会话隔离）：`source="llm_generated"` + `domain_label` +
  `category="动态领域"`，无前端 KB 管理页，纯数据层标记

## 实现

### schema.json 扩字段（前置核对结论）

`additionalProperties: false` → 新增可选 `source`（enum manual/llm_generated）与
`domain_label`；category 枚举加"动态领域"。`practice_questions` 必填 ≥1 →
每节点首题原样注入。`prerequisites` 必须 `^[A-Z]{2}-\d{3}$` → LLM 按 name 互引、
代码映射成 id。

### domain_bootstrap.py（新, ~430 行）

- `resolve_direction(kg, direction, known) -> (hit|miss|unknown, nodes)`：
  LLM 单次分类到域注册表（内置 6 域 + 扫描 JSON 真相源收集的动态域）为主判据；
  LLM 未配置降级向量启发（top ≥0.55）；皆无 → unknown 回退旧选点
- `_domain_candidate_nodes`：语义检索按前缀过滤优先，不足回退难度入口；
  剔除已会节点，**剔尽才放宽**（单测抓出的原设计缺陷：不足 3 个就整体放宽会
  冲掉个性化，题量缺口本就有 LLM 补题兜底）
- `bootstrap_domain`：检索 → 蓝图（LLM，恰好 10 节点由浅入深）→ 出题
  （4 节点/批并发 5）→ 校验（validate_node/validate_question 同源 + 前置仅保留
  更早节点天然无环 + 前缀冲突从领域名推导再字母表扫描）→ 落库（JSON 全量先写 →
  Neo4j upsert → 批量 embedding）。两轮整轮重试，仍不合规 ValueError → 503
- 细节坑：`kb_store.next_node_id` 扫的是磁盘 JSON，落盘前重复调用返回同一序号
  → 起点算一次、进程内递增；qid 同理按 node_id 推导 `Q-{前缀}{序号}-{seq}`

### API 接线（api/diagnostics.py /assess interactive）

miss → `bootstrap_domain`（同步 30-60s）→ 新节点直接出题；hit → 方向子图出题；
unknown → 旧行为。LLM 未配置且 miss → 503「暂未收录且未配置 LLM」明确文案。
`AssessRequest` 加 `tavily_key`（回落 env，对齐 feedback 先例）。
demo 工作流选点**不动**（M5 固定画像基线稳定）。

### 出题 prompt 去硬编码

`_generate_supplement`"补充 Python 理论题"与 `_demo_answer`"正在学习 Python"参数化为
target_direction（demo 画像全是 Python 目标，行为不变）。

### 前端三处

- api/diagnostics.js：interactive 请求 timeout 300s（建域含重试余量）+ tavily_key
  透传；保持"无配置不传第三参"契约（`Object.keys(opts).length ? opts : undefined`）
- assessment store：startAssessment 懒加载 aiSettings 传 tavilyKey（对齐 fetchFeedback
  的 `await import` 防循环依赖模式）
- StageQuiz 出题 loading：「若为新领域将检索资料并构建知识图谱，最长约 3 分钟」

## 追加排查: "新领域知识图谱渲染失败"根因 (IPv6 localhost)

node_id 修复后用户仍偶发渲染失败, 浏览器端复现排查, **根因与动态建域无关**:

1. **localhost -> ::1 (IPv6)**: Windows 下 `localhost` 优先解析 IPv6 (`::1`),
   而后端 uvicorn 只绑 `127.0.0.1:8000`。浏览器/Vite 代理/Node fetch 走
   `localhost` 时间歇撞上 ::1 连接拒绝 (Node 的 DNS 解析序与系统 hosts 相关,
   同机 curl 正常更具迷惑性)。修三处显式 `127.0.0.1`:
   - `frontend/vite.config.js` 代理 target
   - `electron/main/backend-sidecar.js` BACKEND_URL
   - `electron/main/ipc/http-proxy.js` BACKEND_URL
2. **backendHealth.js 浏览器模式永显"后端未起"**: 原实现无条件调
   `window.api.http.request`, 浏览器 dev (无 preload) 下直接 TypeError ->
   状态灯常红误导排查方向。加 axios -> Vite proxy 回落分支。

修复后浏览器完整走通 CSS 动态域全流程: 目标设定秒出 10 题 -> 提交 ->
画像 (正确率 1/10 · 零基础) + 反馈策略 (补前置) + **专属知识图谱阶段正常渲染**。
前端 281 测试全过。

## 追加修复: BFS 重复节点 → G6 "Node already exists" 图谱渲染失败 (2026-08-15)

**症状**: AI 域 (人工智能) 会话服务端全通 (出题/提交/前置/反馈 200), 但第 4 阶段
"专属知识图谱"渲染失败。前端逐节点拉前置的请求序列 (12 请求/9 唯一 id) 实锤
`learning_path` 含重复 node_id (AI-003/004/010 ×2) → G6 graphlib 对重复节点 id
直接抛 "Node already exists" 整图崩。

**根因取证** (直跑实库 cypher-shell, 排除法):
- 库内无同 id 双实体 (`kb_unique_id` 唯一约束在), 节点 252 符合预期 → 排除脏数据
- 直跑 BFS Cypher (AI 域 7 入口): 单次 `WITH n, min(length(path))` 返回
  **42 行/9 唯一** — 实测此模式按 (start,n) 分组不坍缩, 同节点多入口各出一行
  (AI-004 以 d2/d1/d1 三行出现, 恰对应其 3 个入口); 且 `LIMIT` 先在重复行上
  截断, 大域下会饿死唯一节点名额

**修复 (双层)**:
1. engine.py: Cypher 二次聚合 `WITH n, min(distance) AS distance` 真正坍缩到
   全局最短距离 (LIMIT 作用于唯一节点); Python 侧 `seen_ids` 兜底防未来查询回归
   (mock 重复行回归测试守住)。弱项补丁分支原有 `path_ids` 防重, 不受影响
2. 前端 useGraphData: `g6Nodes` 按 node_id 去重 (保首个) + `g6Edges` 按
   source>target 去重 — 后端任何回归都不再炸渲染 (新增 4 个单测)

**验证**:
- 复现场景 (AI 域零基础全错): 修复前 12 节点含 3 重复 → 修复后 **10 节点全唯一**,
  难度 ≤ cap3, 顺序由浅入深
- API 级 E2E: assess(人工智能) 命中复用秒回 10 题 → 全错 submit →
  learning_path 10/10 唯一 PASS
- 回归: 后端 **506** 全过 / 前端 **285** 全过 (281+4 新防御测试)

**AI 域演示数据**: 8-14 晚 E2E 产出的 AI 域 (10 节点 20 题, source=llm_generated)
随本次入库作演示 (与 JV/CS 同模式), Neo4j 侧同步存在 (252 节点)。

## 追加修复: 用户实测三连反馈 — 错域/图谱同色/搜索跑偏 (2026-08-15)

用户以「agent」为目标实测动态建域, 暴露三个问题 (同轮修复):

**① 错域 (题库不匹配)**: 输「agent」1 秒返回 AI 域通识题 (随机森林/CNN/Pandas)。
根因: 域分类器把 "agent" 判给伞形域「人工智能」— 宽泛动态域名会吸收其任何子领域
目标 (agent/CV/NLP…)。修复 (domain_bootstrap.py):

  子领域/专项技术选 new (反例: 「agent 开发」之于「人工智能」通识)
- 注册表动态域附节点名样例 (≤4 个), LLM 对照实际内容判重合度
- resolve_direction 语义复核兜底: LLM 判 known 但目标语义检索 top12 中该域节点
  零出现 → 降级 miss 走动态建域 (检索为空时无法复核, 维持判定)
- 真实 LLM 实测: 「agent」→miss / 「人工智能」→AI / 「机器学习」→ML / 「Java 入门」→JV, 无误伤

**② 图谱无颜色分类**: G6 节点 fill 按 category 着色, 单域学习路径全同 category
(动态域全是「动态领域」) → 全图同色。修复 (KnowledgeGraph.vue + format.js):
节点改难度着色 (≤2 绿/3 橙/4-5 红, 阈值对齐 difficultyTagType), 掌握度改由边框表达
(≥0.8 绿色加粗), 图例弹窗同步 (难度色点+掌握度边框)。masteryColor 保留给 Dashboard。

**③ 联网搜索跑偏**: search_weak_topics 搜索词硬编码 `"Python {节点名} 教程"` —

传入), 搜索词 = `{方向} {节点名} 教程 讲解 示例`; 实测 agent 域弱项搜回 RAG/A2A/MCP 专题。
