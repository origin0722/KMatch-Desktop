## 三、修复过程的关键发现

1. **"LLM 随机性"是误判**：BUG-038 遗留笔记把不稳定归因于 `_demo_answer` 随机作答。systematic-debugging Phase1 强制复现后发现——即使作答固定，mastery 阈值(0.5 vs 0.8)也是确定性错误。**先复现拿证据再归因**，避免把代码 bug 甩锅给 LLM。

2. **BUG-039 暴露链式 Bug**：修 0.8 阈值后，run1/run2 仍打回——因为 `weakness_areas` 还用旧的 `<0.5` 重算，与新的 weak_topics(<0.8)自相矛盾（"无弱项但 weak_topics 有3个"）。一次修复暴露下游不一致，需顺链修完。

3. **BUG-040 是 prompt 语义缺失**：reviewer LLM 凭字段名猜语义（last_test_score→"答对题数"），实际是 mastery×10 掌握分。修复方式不是改字段而是**在审核要点说明字段语义**，让 LLM 不猜。

4. **剩余不稳定确认为赛题预期机制**：系统排查后，剩余打回是 LLM 内容生成**事实幻觉**（编造图谱外的"int 内部表示"等技术细节）被 reviewer 抓到——这正是赛题(4)①"辩论与交叉验证消除幻觉"的预期博弈（加分项），非 bug。4次跑3次通过。

## 五、层次1 减幻觉方案（已实施）

赛题(4)①要求"辩论与交叉验证消除幻觉"——内容生成↔reviewer 打回博弈是核心创新点，**必须保留并在演示中可见**。剩余幻觉通过**层次1（降源头幻觉）**提升通过率，而非靠低温采样（杠杆C，经评估不加——低温不降事实幻觉、且削弱博弈卖点可见性）。

实施（杠杆 A+B，改 prompt 文案，不动函数签名/契约）：

- **杠杆A（主）**：`content_generator._build_generation_prompt` + `_generate_feedback_one` system prompt 强化——显式禁止补充 key_points/summary/common_mistakes 之外的实现细节/内部表示/具体数值/位数/版本号/性能数据（攻击"int 位数组"这类训练记忆幻觉根因），附错误示范负例 + 正向依据要求"每条断言须能在节点信息中找到依据，未提供者留白不补全"。
- **杠杆B（配）**：`reviewer._llm_review_content` 审核要点对齐——明确"只扣编造图谱外事实(实现细节/内部表示/数值等)，不扣图谱未覆盖的技术深度"，避免误打回合理讲解；给负例"int 内部位数组/对象头字节数"。

验证：252 测试无回归（单测用 fake model 不校验 prompt 文本，改动不破坏契约）。减幻觉效果需端到端真实 LLM 跑 assess 验证（reviewer 是否仍误打回），属联调范畴。
