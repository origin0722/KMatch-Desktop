## 七、知识图谱引擎开发（下午追加）

### 7.1 核心引擎 `engine.py`

实现 `KnowledgeGraph` 类（406行），封装全部图谱操作：

| 方法 | 功能 |
|---|---|
| `get_node()` / `get_by_category()` / `get_by_difficulty()` / `get_by_tags()` | 基础图查询 |
| `get_prerequisites()` / `get_dependents()` / `get_reachable()` | 图遍历 |
| `semantic_search()` | 纯向量语义检索（千问 Embedding） |
| `hybrid_retrieve()` | **核心**：图遍历 + 向量检索融合排序 |
| `assemble_learning_path()` | BFS 分层 + 前置依赖补丁的学习路径组装 |
| `update_node_status()` / `get_node_status()` | 节点掌握状态管理 |
| `setup_vector_index()` / `generate_embeddings()` | Neo4j 5.x 原生向量索引 |
| `create_embedding_client()` | 静态工厂方法，自动读取配置创建 embedding client |

### 7.2 LLM 方案确定

| 模块 | 供应商 | 模型 | 接口 |
|------|--------|------|------|
| Chat | DeepSeek V4 Pro | `deepseek-chat` | `api.deepseek.com/v1` |
| Embedding | 通义千问 DashScope | `text-embedding-v2` (1536维) | `dashscope.aliyuncs.com/compatible-mode/v1` |

- Embedding 配置独立于 Chat（`EMBEDDING_API_KEY` / `EMBEDDING_BASE_URL`），如未设置 fallback 到 `LLM_*`
- `create_embedding_client()` 在初始化时验证连通性，不可用时返回 None
- 语义检索在无 embedding client 时静默降级为纯图模式

### 7.3 混合检索算法

```
hybrid_retrieve(known_ids, weak_ids, level, top_k):

  阶段1 — 图遍历（精确）:
    从 known_ids 沿 <-REQUIRES- 反向扩散 2 跳 → 候选集 A（_source='graph'）

  阶段2 — 语义检索（模糊）:
    拼接 weak_ids 的 summary → 千问 embedding → Neo4j 向量索引查询 → 候选集 B（_source='vector'）

  阶段3 — 合并排序:
    A ∪ B 去重 → 按 difficulty 升序 → 同难度按 _score 降序

  阶段4 — 过滤:
    排除 known_ids → 截断到 top_k
```
