## 一、背景

此前添加知识点/题库只能"编辑 JSON 文件 + 跑 import 脚本"，无 API、无管理界面。赛题(1)要"覆盖≥1垂直领域"，项目要可扩展。需要程序化的知识库管理能力作为底座，后续对接前端管理页。

用户决策：
- ID 自动递增（扫该前缀最大号+1）
- **JSON 为源，写后同步 Neo4j**（单源真相，无双写一致性；JSON 是事实底座，Neo4j 是图谱化缓存，符合赛题"知识图谱为共享事实底座"叙事）
- 节点+题目 CRUD 都做
- 暂不扁平化 member_a/b/c（代码用 glob 递归对目录无感）
- A 端独立做后端+测试+文档，不碰前端

## 二、实现

### `app/data/kb_store.py`（新，JSON 真相源层）
- `find_node_file` / `load_node` / `save_node` / `delete_node` — 节点 JSON 定位读写（glob 递归，对 member 目录无感）
- `find_question` / `save_question` / `delete_question` / `load_questions_for_node` — 题目 JSON（`questions/<node_id>.json`）
- `next_node_id` / `next_question_id` — ID 自动递增（正则扫同前缀最大号+1）
- per-file `threading.Lock` 串行化同文件写（参考 B2 修复模式），跨文件并发

### `engine.py` 新增写方法
- `upsert_knowledge_node` — MERGE 节点 + SET 全属性 + 重建 REQUIRES（删旧出边+建新）+ BELONGS_TO，`execute_write` 单事务原子
- `delete_knowledge_node` — DETACH DELETE
- `upsert_question` / `delete_question` / `get_question` / `get_questions_by_node` — 题目 upsert(MERGE+HAS_QUESTION)/删/查
- 字段存储对齐 import 脚本：practice_questions 存 JSON 字符串、key_points/common_mistakes/tags 原生 list

### `api/kb.py`（新，路由 `/api/kb`）
- 节点：POST/GET/PUT/DELETE `/nodes`（DELETE `?cascade=true` 连带删题）
- 题目：POST/GET/PUT/DELETE `/questions`
- 校验复用 `validate_data.validate_node/validate_question`，失败 400+错误列表
- JSON 为源：写 JSON 成功后同步 Neo4j，Neo4j 失败不回滚 JSON、返 warning（可重导修复）
- 节点内容变更后自动重算 embedding
- Pydantic 模型对齐 schema（id/qid 可选自动生成）

### `main.py` 注册 `/api/kb`

### `docs/知识库扩展指南.md`（新）
三种扩展方式：API（推荐）/ 脚本（批量）/ 手动编辑 JSON；含引入新领域流程 + B 端管理页对接契约

## 三、关键设计决策

- **JSON 为源 vs 双写**：选 JSON 为源——单源真相无双写一致性冲突，JSON 可追溯/可重导/版本控制，符合赛题叙事。Neo4j 同步失败不阻塞 JSON 写（可重导修复），API 返 warning。
- **ID 自动递增**：扫全库同前缀最大号+1（PY-092→PY-093，新前缀 ML→ML-001），也允许手动传 id。并发生成撞号由 per-file 锁在 save 时串行化。
- **prerequisites 重建**：update 时 execute_write 单事务包"删旧 REQUIRES 出边+建新"，原子（参考 write_project_graph B3）。
- **cascade 删除**：DELETE 节点默认不删题（防误删），显式 `?cascade=true` 才连带。
- **practice_questions list/str**：JSON 存 list，Neo4j 存 JSON 字符串（与 import 一致），API 读回 json.loads 返回 list。
