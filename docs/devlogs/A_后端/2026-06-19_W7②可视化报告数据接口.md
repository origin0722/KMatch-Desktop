## 一、背景

赛题(3)①要求"生成可视化的个人学情与资源匹配度报告，包含知识盲区定位、资源难度匹配曲线、学习路径规划图"。经核查现状：

- ①知识盲区：数据（demo AssessResponse.profile.weak_topics）+ 渲染（Assessment.vue）已齐。
- ②资源难度匹配曲线：原料齐（demo 的 resource.difficulty_level + node.difficulty + mastery），但**无预计算、Dashboard.vue 纯占位**。
- ③学习路径规划图：demo 有 knowledge_graph 数据但无组件渲染（GraphDemo 用硬编码 mock）；**interactive 模式 submit 不返回 knowledge_graph/generated_content**——真实答题用户拿不到路径和内容。

用户确认：**demo 和 interactive 两种模式都要支持完整可视化**。

---

## 二、方案：混合架构

解耦"快反馈"与"慢报告"：
- **demo**：assess 一次跑完 workflow，内联计算 `learning_report` 嵌入 AssessResponse（新增字段，默认 {} 不破坏契约）。
- **interactive**：submit 保持轻量（仅判分+画像+反馈）；新增 `POST /api/learning/report`，B 端进报告页时按需补跑 graph_controller+content_generator+reviewer（单轮，不回环），幂等缓存。

**interactive 补跑跑单轮 reviewer，不循环**：赛题(4)①要求抗幻觉，内容必须审核；单轮足够（完整回环是 demo workflow 职责），不通过则诚实降级交付（passed=False+retry_hint）。0.85 阈值全程不降。

## 三、实现

### 新增 `backend/app/agents/report_builder.py`
纯函数 `build_learning_report(profile, knowledge_graph, generated_content, review_results, kg=None) -> dict`，三子对象对应三类可视化：
- `blind_spots`：仅被测节点，mastery 升序，三段制 status（mastered/learning/weak），name/difficulty 从 learning_path 富化。
- `difficulty_match`：per-resource 粒度，gap=resource_difficulty-node_difficulty 带符号，match_status 用 |gap|<=1 阈值（确定性可单测）。
- `learning_path`：G6 友好 nodes/edges，PATH_SEQUENCE（相邻恒有）+ REQUIRES（kg 可用时取路径内前置，尽力而为）；is_current=recommended_path.current_node。
- 纯函数不调 LLM；REQUIRES 边 kg 作可选参数。

### 新增 `backend/app/api/learning.py`
- `POST /report`：校验序 session(404)→profile(409)→LLM(503)→kg(503)→补跑。
- 补跑绕过 LangGraph 直接 fold 调用 node 函数（签名 (state)->delta，已验证），手动追加 orchestration_log（绕过 Annotated reducer）。
- 幂等：首次补跑后回写 session 缓存（knowledge_graph/generated_content/review_results/learning_report_cache），二次调用毫秒级返回。
- 从 diagnostics 导入 `_INTERACTIVE_SESSIONS`（模块级 dict 引用，非循环）。

### 修改 `backend/app/api/diagnostics.py`
- AssessResponse 新增 `learning_report: dict = Field(default_factory=dict)`。
- demo 分支 return 前调 build_learning_report 内联填充；interactive 出题分支留空。
- submit 分支新增 `session["profile"] = profile` 回写（供 /api/learning/report 读取，仅需 session_id）。

### 修改 `backend/app/main.py`
注册 `/api/learning` 路由（取消预留注释）。

### 复用不改
graph_controller_node / content_generator_node / reviewer_node 均为 (state)->delta 纯调用，可绕 LangGraph 直接 fold。

## 四、关键设计决策

1. **difficulty_match 选 per-resource 而非 per-node**：1 节点 3 段资源难度可能不同，per-resource 无损，B 端可聚合可细画；gap 带符号直接做曲线 y 轴。
2. **match_status 用 gap 阈值不用 mastery 启发式**：确定性、可单测、可解释；mastery 作独立字段保留供 B 端叠加。
3. **REQUIRES 与 PATH_SEQUENCE 去重分离**：同 (source,target) 不同类型可共存（修复了初版按 (s,t) 互斥去重导致 REQUIRES 被 PATH_SEQUENCE 吞掉的 bug）。
4. **demo 不传 kg（仅 PATH_SEQUENCE），interactive 传 kg（含 REQUIRES）**：demo 内联计算免 kg 调用，interactive 补跑有 kg 取前置依赖，两者互补。

## 六、B 端对接说明（交付 B 端）

Dashboard/Learning 页可视化报告数据来源：
- **demo 模式**：`AssessResponse.learning_report`（assess 一次返回，含 blind_spots/difficulty_match/learning_path 三子对象）
- **interactive 模式**：`POST /api/learning/report {session_id}`（submit 后按需调用，首次 ~90s 补跑，二次秒回缓存）

三类可视化字段：
- 知识盲区热力图：`learning_report.blind_spots.nodes`（mastery 升序, status 着色）
- 资源难度匹配曲线：`learning_report.difficulty_match.points`（gap 做 y 轴, match_status 着色, path_position 做 x 轴）
- 学习路径规划图：`learning_report.learning_path.nodes` + `edges`（G6 直接消费，PATH_SEQUENCE 主线 + REQUIRES 前置依赖）
