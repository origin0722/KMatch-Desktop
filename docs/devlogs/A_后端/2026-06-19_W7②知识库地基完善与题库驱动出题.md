## 一、背景

审计发现知识库地基三个实质问题：

1. **common_mistakes 全缺** — 92节点全无此字段（schema 也没定义），但它是5处运行时Agent消费的真有用字段（content_generator test干扰项/diagnostics error_patterns/code_tester/code_reviewer/reviewer事实边界）。不补则BUG-036修复在真实数据失效、层次1减幻觉的"依据common_mistakes"落空。
2. **practice_questions 是死数据** — diagnostics出题根本不读题库，LLM现场基于key_points造choice+judge题。AI生成题目入题库对测评无影响。
3. **题目存节点属性难检索** — practice_questions作为KnowledgeNode属性JSON字符串存，无法按题型/难度高效检索，且engine不反序列化。

三个隐藏缺口（调研新发现）：① practice_questions import时json.dumps存string但engine不反序列化；② 题库题无node_id字段，_grade/_build_profile按node_id分组丢掌握度；③ common_mistakes若误用json.dumps存string则mistakes[0]退化为首字符。

用户决策：题目独立成`:Question`节点+`:HAS_QUESTION`关系（追求演示高效+个性化+无幻觉）+ 题库驱动出题 + 一次性全做 + AI生成为主 + common_mistakes LLM草稿人工审。

---

## 二、方案：独立Question节点 + 题库驱动出题

数据建模变更：**题目从节点属性升级为独立`:Question`节点**。

```
:KnowledgeNode (id/name/difficulty/.../common_mistakes[list])
   | :HAS_QUESTION
   ▼
:Question (qid/source_node_id/type/question/options/answer/difficulty/hint/explanation)
```

- common_mistakes仍存KnowledgeNode属性（原生list，5处消费点不变）
- Question节点建索引（source_node_id/type/difficulty）支撑高效检索
- 题目预生成+审核后入库（无幻觉），出题直接Cypher查（不卡）

## 三、实现（10步依赖序）

### 数据生成（脚本）
- `generate_common_mistakes.py`：LLM为92节点生成common_mistakes（2-4条list[str]，严格基于summary/key_points，复用层次1高保真约束），8并发生成，写回节点JSON。**92节点全部成功**，质量好（如PY-001："int有固定位数上限""字符串可用索引修改字符""bool与int无关"——真实常见错误）。
- `generate_practice_questions.py`：LLM按difficulty生成题目（diff1-2=2choice+1fill，diff3+=1choice+1fill+1code），choice干扰项来自common_mistakes，code题ast.parse轻校验，输出`questions/<node_id>.json`。**276题**（choice126/fill92/code58），题型均衡（之前choice36/code76/fill5严重偏科）。高难度节点(PY-080~092)LLM偶发失败，逐个低并发重试补齐。

### 数据规范
- `schema.json`：加common_mistakes属性（array string minItems1 maxItems6）；judge不入enum（放弃判断题）。
- `validate_data.py`：加common_mistakes校验 + per-question difficulty校验 + 题目结构校验（读questions/校验qid/source_node_id/type/answer/options）。

### 导入

### 查询
- `engine.py`：新增`get_questions`/`get_questions_for_nodes`/`_question_from_record`，Cypher按type/difficulty筛选走索引，options反序列化，注入node_id=source_node_id别名（供_grade/_build_profile分组）。

### 出题（核心）
- `diagnostics.py`：新增`_select_from_bank`（调kg.get_questions_for_nodes抽choice/fill，注入node_id，random.shuffle保证不重复，seed可复现）+`_build_supplement_prompt`/`_generate_supplement`（不足LLM补差额，复用_node_facts_text公共函数）；改造`prepare_questions`（题库优先+LLM补，LLM未配置+题库空raise ValueError）；`_demo_answer`小改（options仅choice题显示，fill题显示填空题）。放弃judge（运行时题型，信息量低）。

## 四、关键设计决策

1. **放弃judge题型** — schema无、信息量低（answer="对"/"错"），choice精确判分+fill LLM语义判分已覆盖理论考察。code题不抽（无法可靠LLM判分，留给content_generator/code_tester）。
2. **题目独立Question节点**（非节点属性）— 可按题型/难度Cypher高效检索（演示不卡）、题可共享、增删题不影响知识节点。建3个索引。
3. **common_mistakes原生list存储** — Neo4j支持list[str]，5处消费点.get直接拿list（若误json.dumps存string，mistakes[0]退化为首字符）。
4. **_select_from_bank注入node_id** — 题库题的source_node_id作node_id别名，_grade/_build_profile按node_id分组不丢掌握度。
5. **max_per_node=2** — 每节点最多2题，保证10题覆盖多节点（个性化），非单节点堆题。
6. **code题ast.parse轻校验** — 不接code_tester（集成工作量大，后置），--validate-code统计通过率供人工审。
