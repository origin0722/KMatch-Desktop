# 2026-08-14 后端重构 R1-R4 - 消除 Spec B 脚手架与知识上下文重复

> 后端代码体检后发现 4 处低风险机械重复，统一提取为共享工具。488 后端测试全过，行为零变化。

## 改动清单

### R1: Spec B override 脚手架提取 (llm.py + 3 agent)

**问题**：diagnostics / content_generator / reviewer 三个 agent 节点各有相同的 `_node` wrapper（读 `state["llm_overrides"]` -> set ContextVar -> try/finally reset），content_generator 还有 `_safe_generate` / `_safe_feedback` 两个几乎逐行相同的 ThreadPoolExecutor worker wrapper。

**方案**：

- [llm.py](../../../backend/app/agents/llm.py) 新增两个复用工具：
  - `@with_state_overrides` 装饰器：包 LangGraph 节点 `_node(state)`，自动从 `state["llm_overrides"]` set/reset ContextVar。无 overrides 时 no-op。
  - `safe_llm_call(fn, *args, overrides=, logger=, label=)` -> `(ok, result|None)`：ThreadPoolExecutor worker 包装，线程内重设 ContextVar + 异常不外抛。

- 三个 agent 节点 `_node` 改用 `@with_state_overrides`，删除各自的 try/finally boilerplate。
- content_generator 的 `_safe_generate` / `_safe_feedback` 内部函数删除，`pool.map` 直接调 `safe_llm_call`。

### R2: `_build_knowledge_context` 提取到共享模块

**问题**：code_reviewer.py 和 code_tester.py 各有一份 `_build_knowledge_context`，逻辑几乎一致（遍历知识节点拼 LLM 上下文字符串），仅 reviewer 版多了 key_points 输出。

**方案**：提取到 [knowledge_context.py](../../../backend/app/agents/knowledge_context.py)，参数化 `include_key_points` / `empty_hint`。两个 agent 改用共享函数。

### R3: graph_controller 空图谱 dict 提取

**问题**：graph_controller `_node` 里「画像为空」和「组装异常」两条路径各手写同一个 5 字段空 dict。

**方案**：提取 `_empty_kg_result(log)` helper，两处复用。

### R4: `CONTENT_GEN_CONCURRENCY` 提升到 settings

**问题**：content_generator 在函数体内 `import os` 读环境变量。

**方案**：移到 [config.py](../../../backend/app/config.py) `settings.CONTENT_GEN_CONCURRENCY`（默认 5），content_generator 直接引用。
