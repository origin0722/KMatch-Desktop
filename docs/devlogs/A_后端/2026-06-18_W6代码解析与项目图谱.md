### engine.py 加 5 方法（项目图谱分区）
- `write_project_graph`：DETACH DELETE 旧实体 → 分 label 三批 CREATE → 建三类关系

### 关键设计
- **命名空间隔离**：项目实体打 `:ProjectEntity` 基标签 + Module/Class/Function 子标签，绝不打 `:KnowledgeNode`，与领域元知识 PY-xxx 物理隔离
- **entity_id**：`PROJ-{pid}-{TYPE}-{qualified_name}`
- **Neo4j 属性限制**：节点属性不支持 list of map，params/external_calls 序列化为 JSON 字符串存储，读取时还原
- **方法建模**：单一 `:Function` label + `is_method`/`parent_class_id` 区分方法
- **Jedi 价值**：解析 `crawler.crawl()`（局部变量）、`self.fetch_page()` 这类纯 AST 无法解析的语义调用

## 三、深度审查修复的 Bug

开发中深度审查发现并修复 1 个真实 bug + 加固若干点：

1. **ClassDef 重复调用收集（已修）**：原对类节点 `_collect_calls(node, cls_entity.entity_id, ...)`，`ast.walk` 遍历整个类体含方法体，把方法调用错误归到类实体并与方法重复。修复：类是容器，只对各方法收集调用，类实体 external_calls 为空。

2. **Jedi col 位置（已修）**：初版用 Call.col_offset（指向 `self`）infer，jedi 返回的是 self 类型（类）而非被调方法。修复：Attribute 调用 col 精确到 attr 标识符位置（value.end_col_offset + 1）。

3. **resolved 标志 + 回退条件（已修）**：jedi_resolver 初版回退条件 `if target_id is None and script is not None` 导致 Jedi 初始化失败时不回退；且 Jedi 空但回退成功时 resolved 误标 True。修复为两阶段（Jedi→回退），resolved 仅 Jedi 成功时 True。

4. **fake session 兼容（测试基建）**：_FakeResult 同时支持迭代（get）和 .single()（delete）。

5. **多文件限制标注**：loader.parse_project 加注释，说明 entity_id 不含 module_name 多文件会撞、Jedi 跨模块解析受限（本批单文件，下批处理）。
