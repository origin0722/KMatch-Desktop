## 背景与调研

用户反馈四个问题，其中图谱优化参考了两个开源项目（web 调研结论）：

- **archify** (tt-a1i/archify)：Agent skill，LLM 只产出类型化 JSON 中间表示，布局/渲染交给确定性编译器 + 交付前校验（render-and-verify）。
- **excalidraw-skill** (Agents365-ai/excalidraw-skill)：skill 规范化设计系统 — 8 色语义盘、CJK 感知尺寸（全角字符按 ~2× 宽计）、间距/折线路由规则、防呆清单 + 确定性渲染。

两者共同哲学：**LLM 做判断、确定性代码做渲染**。本次整改将该哲学落进产品：布局尺寸全部由纯函数计算（可测、零幻觉），excalidraw 导出走确定性转换器（不让 LLM 写坐标）。

## 同日追加: AI 助手四项优化 (用户评审后采纳)

来源：对 AI 助手链路 (chat store → SSE 传输层 → 主进程 http 代理) 的专项评审，按「收益 × 成本」优先级落地 P0 三项 + P1 对话持久化：

1. **历史窗口裁剪** (`buildApiHistory`, chat.js)：此前每次请求把全部可见消息塞进上下文，长对话 token 无限膨胀直至溢出报错。现按 48k 字符预算从头裁最旧，最后一条 user 消息（当前回合锚）永不被裁，裁后保证以 user 开头；sendMessage 与 regenMessage 共用。
2. **流式滚动守卫** (AssistantPanel.vue)：此前流式输出每次内容变化都强制滚底，用户上翻阅读被不断拽回。现距底 >80px 自动暂停跟随 + 输入区上方「↓ 回到底部」浮动按钮；用户主动发送时强制回底。
3. **IPC 流看门狗 + 真·停止** (useChatStream / preload / http-proxy)：桌面端此前 (a) 无流超时看门狗（后端挂起永远转圈）——补 150s 无数据断流判定，与浏览器路对齐；(b) 点「停止」只解除前端等待、上游 LLM 请求继续跑完烧 token——新增 `http:stream:abort` IPC 通道，主进程按 reqId abort 上游 fetch，渲染层 abort 时同步通知。
4. **对话持久化** (chat.js)：此前纯内存、重启全丢。现 store 初始化从 localStorage 恢复（`kmatch-chat-history`），变更 800ms 防抖回写；图片附件不入存储（体积），保留文本与助手消息分支结构（重启后 regen/版本导航仍可用）；1.5MB 兜底从头裁最旧；「清空对话」同步清存储。

测试：新增 chat-history.test.js（9 用例）+ useChatStream 看门狗/真停止（3 用例），前端全量 **507 通过**；electron 两文件 node --check 通过；vite build 绿。
