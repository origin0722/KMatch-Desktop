# 项目图谱深度增强：实体丰富化 + 技术栈检测 + LLM 分析 + 联网搜索

> 阶段18 | 2026/08/15 | 后端 + 前端

## 背景

用户反馈："这个项目图谱只是表面，没有深层的去解析，更没有在此基础上没有联网搜索学习资源去辅助"。

根因分析：
1. **数据断层** — 后端 `parse_project` 已提取 docstring/params/return_type/bases/decorators/external_calls/source_code 等丰富属性，但前端 `normalizeGraphResponse` 只保留 6 个字段（id/name/kind/qualified_name/line_start/line_end），其余全丢弃
2. **无技术栈检测** — `external_calls` 已捕获未解析外部调用名（`requests.get`/`pandas.DataFrame`），但从未聚合分类
3. **无 LLM 分析** — `parse_project` 纯 AST，无语义层面的架构解读
4. **无联网搜索** — `search_web` + `learningResources` store 已就绪，但 ProjectGraphView 完全未接入
5. **Stats bug** — 后端返回 `function_count`，前端读 `function`，头部计数永远 0

## 设计：两段式（AST 自动 + LLM 按需）

AST 能做的（技术栈检测、实体属性展示）自动执行零成本；LLM 分析 + 联网搜索按需触发（按钮），不拖慢自动解析。

## Phase 1：修复数据断层 + 实体详情丰富化（零 LLM, 自动）

### `api/project.js` `normalizeGraphResponse` 传递完整属性
- entities 新增：docstring, params, return_type, bases, decorators, external_calls, module_name, source_code, is_method
- 新增 `_parseJsonField` helper：Neo4j 存 JSON 字符串的列表字段安全解析
- 新增 `_mapStats` 函数：后端 stats key（`function_count`）映射到前端期望的短 key（`function`），修复头部计数 bug

### `ProjectGraphView.vue` 实体详情面板丰富化
- docstring 折叠展示（`<pre>` + 可展开收起）
- 参数列表 params（名称:类型）
- 外部依赖 external_calls（去重后 top-level 模块名，tag 形式）
- 继承基类 bases、装饰器 decorators（如有，tag 形式）

---

## Phase 2：技术栈自动检测（AST, 零 LLM, 自动）

### 新建 `frontend/src/utils/techStack.js`
- `detectTechStack(entities)`：扫描所有实体的 `external_calls`，提取 top-level 模块名，映射到技术分类
- 内置 40+ 常见 Python 包映射表（flask→Web 框架, pandas→数据分析, requests→HTTP 客户端, pytest→测试, torch→机器学习 等）
- 返回 `[{name, category, count}]`（按引用次数降序），同技术别名合并去重

### `ProjectGraphView.vue` 头部技术栈 badges
- stats 行下方新增技术栈 tag 行
- 点击 tag → 调 `/api/search/web` 搜该技术的学习资源 → 流入 `learningResources` store → 提示到学习视图查看

---

## Phase 3：LLM 深度分析 + 联网搜索（按需）

### 后端 `backend/app/agents/project_analyzer.py`（新文件）
- `analyze_project(kg, project_id, tavily_key)`：
  1. 从 Neo4j 取项目图谱 → 构建实体摘要（名称/类型/调用关系/外部依赖/docstring）
  2. LLM 分析架构（模式/入口点/关键模块/复杂度/学习建议），输出结构化 JSON
  3. 对检测到的技术栈逐个 `search_web` 搜教程文档（每项 2 条）
- LLM JSON 解析容错：去 ` ```json ` 包裹，解析失败降级为纯文本 summary
- 复用 `app/agents/llm.py` 的 `get_default_chat_model` + `llm_configured`
- 复用 `app/utils/web_search.py` 的 `search_web`

### 后端路由 `POST /api/project/analyze`
- 入参 `{project_id, tavily_key?}`
- 503 if Neo4j 未就绪 / LLM 未配置；404 if 项目图谱不存在
- 返回 `{summary, architecture, complexity, recommendations, tech_stack, web_resources}`

### 前端 `api/project.js` 加 `analyzeProject(projectId, tavilyKey)`

### 前端 `projectGraph store` 加 `analyze()` action
- `analyzing` ref (bool) + `analysis` ref (null|结果对象)
- 调 `analyzeProject` → set analysis → web_resources 流入 `learningResources` store
- 错误提示用后端 detail 文案

### `ProjectGraphView.vue` 加"深度分析"按钮 + 结果面板
- 工具栏新增"深度分析"按钮（warning 样式, loading 状态, 无图谱时 disabled）
- 侧栏新增"项目分析"卡片（analysis 非空时显示）：
  - 架构摘要 summary
  - 架构模式 + 入口点 + 关键模块
  - 复杂度（低/中/高，颜色区分）
  - 学习建议列表
  - 联网资源列表（点击在新窗口打开，标注所属技术）
