# Git 仓库面板（方案A）— 像 VS Code 一样拉取/提交/推送

日期: 2026-08-23
范围: Electron 主进程 + preload + 前端 (frontend/src)
涉及版本: v1.0.13 落地 → 随正式版 v1.1.0 发布 (issue #93, label enhancement)

## 背景

用户问：「项目功能中用户可不可以像 VSCode 那样远程拉取仓库并提交更改之类的，毕竟植入了终端」。

排查结论：右侧「日志」面板是**编排/运行日志**，不是可交互 shell；产品里没有真实终端。
给出两案后用户选择 **方案A = Git 面板**（主进程调系统 git CLI + Git 视图），
不做真实 PTY 终端（终端属重资产：pty 依赖、shell 注入面、无边框窗口内嵌控制台复杂度高）。

## 交付内容

### 1. 主进程 IPC — `electron/main/ipc/git.js`

- 全部走 `execFile('git', argsArray, {cwd, windowsHide})`，**无 shell 拼接**，无注入面；
- 统一返回 `{ ok, output }` / `{ ok:false, error }`；
- 通道：`git:check`（版本探测）/ `git:status`（`status --porcelain=v1 -b` →
  `{ isRepo, branch, files:[{status,path}] }`，优雅识别"not a git repository"）/
  `git:init` / `git:clone`（主进程弹目录选择器 → 目录名取 URL 末尾 → `git clone`；
  返回 `root` 供渲染层 `setRoot` 自动切项目）/ `git:pull` / `git:commit`
  （`-m` + 可选 `add -A`）/ `git:push` / `git:log`（`--oneline --decorate`）；
- 凭据：HTTPS 依赖用户系统 git 配置/凭据管理器/个人 token，**应用不保存任何密钥**；
- 长命令超时：clone/pull/push 180–300s，其余 60s。

### 2. preload — `window.api.git.*`

按既有命名空间风格（`workspace/fs/http/window/docker`）暴露 8 个方法，
渲染层无 Node 能力，继续维持 contextBridge 受控表面。

### 3. Git 视图 — `frontend/src/ide/GitView.vue`

导航侧栏新增「Git 仓库」（`ACTIVITY_ITEMS`，MainArea 新增分支，懒加载）。五个状态：

1. **未检测到 Git** → 居中空态 + Git for Windows 下载链接 + 重新检测；
2. **未打开项目** → 克隆远程仓库 / 打开本地项目；
3. **已打开非仓库** → 初始化 Git 仓库 / 克隆远程仓库；
4. **仓库面板**：分支徽标 + 拉取/推送/刷新；更改文件列表（未跟踪/新增/修改/删除/
   重命名/冲突着色）；提交区（textarea + 「暂存全部并提交」）；最近 10 条提交
   （hash + message）；命令输出（成功/失败配色）；
5. 克隆成功 → `workspace.setRoot(克隆目录)` → 自动触发文件树加载 + 项目图谱
   后台解析（复用既有 `onProjectOpened` 链路）。

### 4. 单测 — `frontend/src/__tests__/git-view.test.js`

mock `window.api.git` + `ElMessageBox.prompt`，真实 pinia workspace：
覆盖未装 Git / 未开项目 / 非仓库 / 仓库渲染 / 提交清空输入 / 克隆后 setRoot /
拉取推送 / 初始化，共 8 例。

## 测试

- 前端全量：**62 文件 / 467 用例全过**（459 + 8 新增）。
- 后端无改动（本功能纯前端 + 主进程），无需重跑后端 PyInstaller 之外的动作。

## 已知边界

- 无真实终端：不做交互 shell；纯命令按钮流（克隆/状态/拉取/提交/推送/历史）。
- 冲突合并 / 分支切换 / rebase 等高级操作本期不做（`git pull` 失败时错误信息原样
  上浮，用户可按输出处理）。
- Git 必须已安装且 `git` 在 PATH（安装包不捆绑 git）。
