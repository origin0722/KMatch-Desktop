## 二、关键决策

- **worker_threads 而非主进程内**: 赛题定位"垂直领域专业化知识与智能体协同决策", 项目规模可能泛化到其他 AI 垂直领域 (含数据集/模型文件大目录)。主进程内跑 chokidar 会让 IO 回调卡 UI; worker_threads 隔离保证主线程流畅。Apix 原样方案。
- **chokidar v4 非 v5**: v5 ESM-only 与 electron-vite main 的 CJS 输出冲突 (顶层 import 在 CJS bundle 里报 ERR_REQUIRE_ESM)。v4 支持 `require`, 兼容; 复用已有 picomatch 依赖。
- **Worker 用 .cjs + rollup 多入口**: electron-vite main 输出 CJS, worker 作为 `rollupOptions.input` 第二入口 build 到 `out/main/watcher-worker.js` (chokidar 内联 54.81 kB)。Node `new Worker(path)` 直接 require 运行。lib.entry 与 input 冲突 → 去掉 lib.entry, 用 input + output.format=cjs。
- **纯工厂 + 依赖注入**: `createWatcherController({Worker, getMainWindow})` 对齐 `window-ipc.test.js` 验证过的可测模式。worker_threads/electron 通过 `vi.mock` + `importOriginal` 注入, fake Worker 用普通函数 (箭头函数不能 `new`)。
- **S6 三件强协同**: v-show 常驻 Monaco 后 model 永缓存, 必须有 watcher 推送外部变动失效才完整 (否则外部改文件 Monaco 显示陈旧); 图谱失效只有 watcher 能驱动 (无变动通知不知何时过期); 三者共享同一"文件变动事件"管线, 一次做完。
- **冲突二选一**: dirty 文件被外部改时弹"保留编辑/加载磁盘", 不做三向合并 (成本高, 学习 IDE 不需要)。

## 三、赛题功能影响

- **场景二 (有项目二次开发) 正确性修复**: 项目图谱是一次性快照, 实体带生成时刻行号。文件编辑保存后行号漂移, 原 Monaco 符号联动会跳错误行 — 赛题演示时评委点实体跳错行即露馅。本次加 stale 标记, 源文件变动后 AssistantPanel 提示"图谱已过期"并禁用跳转, 避免误导。
- **垂直领域泛化**: worker_threads 隔离 IO, 未来监听大目录 (数据/模型文件) 不卡 UI。
- **IDE 专业性**: 外部改动自动同步 + 冲突确认, 对齐 Apix/VSCode 级编辑器体验。
- **零功能回归**: 文件树刷新/编辑器保存/图谱联动/chat 工具循环行为不变; 既有 80 测试全过。
