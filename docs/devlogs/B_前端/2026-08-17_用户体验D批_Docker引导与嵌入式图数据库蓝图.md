# Docker 引导第一阶段 + 嵌入式图数据库方案蓝图

> 用户体验第一批 D 批 | 2026/08/17 | Electron 主进程 + 前端

## 背景

目标用户安装桌面版 KMatch 后，**Neo4j 仍未就绪**是一个高频断点：装完安装包 → 应用起来 → 后端起 → 但图谱全部不可用，且没有任何引导解释“为什么”。此前唯一的入口是深藏在 README 里的 `docker-compose up -d`。

本批做两件事：
1. **引导通道**（本阶段落地）：探测 Docker → 差异化引导（已装 → 一键复制启动命令；未装 → 官网链接 + 受限模式说明）。
2. **方案蓝图**（文档先行）：中期评估把 Neo4j 换成本地嵌入式图数据库（LiteGraph / Kuzu），消灭 Docker 依赖，一装即用。

## 二、设计要点

### 引导状态机（渲染层组合后端 + 主进程信息）

```
后端 /api/health.neo4j  →  connected / unavailable
Docker 探测             →  installed / not-installed
```

- 后端未起：状态栏只显示"后端未起"（原有行为不动）
- 后端起 + 图库已连：不显示引导入口
- 后端起 + 图库未连：显示"图库未连"入口
  - Docker 已装 → 一键复制 `docker-compose up -d` + 重新检测
  - Docker 未装 → Docker Desktop 官网链接 + **受限模式说明**（测评/对话/内容生成仍可用，图谱检索与路径规划不可用）

### 实现细节

- `docker --version` 用 `spawn` + `stdio:['ignore','pipe','pipe']`，参考 `backend-sidecar.js` 必须挂 `error` 处理器（ENOENT 不挂 error 会触发未捕获异常黑屏）。
- 3s 超时兜底：Docker Desktop 冷启动时命令可能挂起，超时判未就绪并给提示。
- `backendHealth.check()` 对 `res.body?.neo4j` 做防御性解析：Electron 代理返回 `{ok, status, body}`；浏览器 dev 走 axios 返回 `{data}`；`startsWith('connected')` 判定——测试 mock 只给 `{ok,status}` 时 `neo4jStatus` 保持 `unknown`，不破坏既有 5 个单测。

## 三、嵌入式图数据库方案蓝图（中期, 未实施）

### 目标

消灭 Docker 依赖：安装包内嵌图数据库引擎，应用启动即用，无部署步骤。

### 候选方案对比

| 方案 | 类型 | 体积 | 持久化 | 查询语言 | 风险 |
|:---|:---|:---|:---|:---|:---|
| **LiteGraph** (litedb) | 嵌入式纯 JS/TS | ~2-5MB | 文件（SQLite 系） | GraphQL-ish JS API | 生态新, 复杂图算法弱 |
| **Kuzu** (Kùzu) | 嵌入式 C++ / Node 绑定 | ~10-20MB (native) | 文件 (列式) | Cypher 子集 | 需 electron-rebuild, 跨平台 native 打包 |
| 保留 Neo4j + Docker | 外部服务 | 0（用户装 Docker） | Docker volume | 完整 Cypher | 引导成本高, 离线不可用 |
| 降级为纯内存图 + JSON 落盘 | 自研 | 极小 | 文件 | 自研遍历 | 失去 Cypher/索引/Lucene 式检索 |

### 推荐路径（分三步）

1. **抽象数据访问层（先行, 零风险）**：后端 `app/graph/engine.py` 目前直连 Neo4j Bolt。抽出 `GraphStore` 接口（`query/import/upsert/vector_search/path`），Neo4j 实现保留为默认后端。前端/Agent 只依赖接口，不依赖 Neo4j 特性。
2. **Kuzu 嵌入式实现（对标 Cypher 子集）**：迁移四层图谱 + 向量检索（Kuzu 支持 embedding 列 + cosine 相似度）。完成度验证 = 现有 488 后端单测全过 + 知识库导入脚本等价产出。
3. **按环境切换**：`GRAPH_STORE=neo4j|kuzu` 环境变量；有 Docker 用户继续用 Neo4j（数据可导出互通），无 Docker 用户默认 Kuzu。安装包直接带上 Kuzu native 模块（注意 electron-rebuild + 多平台）。

### 决策门槛（何时启动三步中的第 1 步）

- [ ] 装机用户中"无 Docker 环境"占比显著（安装包分发后观察引导页点击/反馈）
- [ ] Kuzu Node 绑定在目标三平台（Win/macOS/Linux）electron 33+ 下验证可用
- [ ] 图谱查询面收敛（当前 engine.py 实际用到的 Cypher 模式 < 30 个）

### 蓝图落地前的过渡（本批已完成）

- 状态栏 + 设置页双入口引导，把"图库未连"从静默失败变成可解释、可执行
- 为第 1 步预留心智模型：`backendHealth.neo4jStatus` 已是渲染层单一真相源，换引擎不涉及 UI 改动
