## 三、四项真冲突详解

### 3.1 BUG-023 — `nodeCorrect` filter(Boolean) 漏洞

**为什么本次审查能发现而 B-2 修复时没发现**：

B-2 当时的关注点是"`questionList` 这个 computed 怎么按 `question_index` 索引"，思维焦点在"题目明细列表"。但 `per_node` 在该组件中有**两个消费点**：
- `questionList` — 按 `question_index` 反查（已修）
- `nodeCorrect` / `nodeTagType` — 按 node 聚合（**漏改**）

B-6 写单测时也只测了 `questionList` 的两个分支，未测 `nodeCorrect`，单测无法捕获此 bug。

**教训**：数据结构变更后，不能只看"显眼的消费点"，要全文 grep 该字段的所有读取点。本次修复后 vitest 30 用例全通过，新增的 4 条 `nodeCorrect` 用例如果跑在旧实现上会全部失败（验证回归覆盖有效）。

### 3.2 BUG-024 — 项目速查卡 模型名

低工作量但高优先级。新协作者读 项目速查卡 第一份文档就被误导，会以为代码在用 OpenAI 的模型，可能误改 `config.py` / `.env`。

### 3.3 BUG-025 — `recommended_path` 三方错配（不在本次会话修复范围）

涉及后端代码 + prompt + Schema 三方修改，跨 A/C 目录归属，**不在 B 端会话范围内**。已写入审查报告与 BUG 日志，留给 A/C 认领（采纳"扩展 diagnostics 输出为 object"方案）。

### 3.4 BUG-026 — `_grade` 顺序依赖治标未治本（不在本次会话修复范围）

BUG-022 把 `per_node` 升级为带 `question_index` 的对象结构，但后端写入的 `question_index` 仍是 grades 数组下标。LLM 漏题/乱序时新前端依然指错题目。

留给 A 修：判分 prompt 让 LLM 显式回写真实下标 + 后端边界 fallback。

## 五、踩坑

### Pitfall-1: vitest 暴露组件内部函数需挂在 `<script setup>` 顶层

`nodeCorrect` 是 `<script setup>` 中的普通函数，默认不在组件 instance 上暴露。
之前的 `assessment-report.test.js` 用 `wrapper.vm.questionList` 能直接拿到 computed（Vue 自动暴露）。但 `nodeCorrect` 是 function，需要 `wrapper.vm.nodeCorrect(...)` 调用才行。
**实测**：Vue 3 的 `<script setup>` 在 `defineExpose` 没显式声明时，所有顶层定义的 const/function 都通过 setup return 暴露给 vm（这是 vue-test-utils 的"隐式暴露"行为）。本次单测直接 `wrapper.vm.nodeCorrect(arr)` 可用，未踩坑。
**记录**：生产代码若加 `defineExpose({ ... })` 显式列白名单，需注意把测试需要的函数也加进去。

### Pitfall-2: 中文目录名在 git bash 下的命令行兼容

`docs/devlogs/B_前端/` 在 git bash 下 `ls` 会因 GBK/UTF-8 转义失败。
**解决**：要么用绝对路径 `ls "f:\KMatch\docs\devlogs\B_前端\"`（Windows path），要么换 PowerShell。本次会话用 cd 到项目根目录后 `ls docs/devlogs/B_前端/` 也能正常工作（path resolution 走 Win32 API）。

### Pitfall-3: `git add docs/` 一次性加带中文文件名的 BUG 日志

git status 输出会用 8 进制转义中文，但 `git add docs/` 仍然按字节路径正确添加。无须特殊处理。
