# 2026-08-13 学习会话三处问题修复 + Agent 协同面板重做

> 用户桌面验收知识图谱扩域后反馈 3 个问题，逐项修复 + Agent 协同展示从"原始日志"重做为"产出概览"。

## 问题 1：目标设定方向横排看不见

扩域后 StageGoal 的 `presetDirections` 从 6 增到 11（+5 新域），原 `.direction-row` 用 `overflow-x: auto` + 隐藏滚动条，后段方向被裁不可见。

**修复**：`frontend/src/components/session/StageGoal.vue` `.direction-row` 改 `flex-wrap: wrap`（自动换行，11 方向全可见；隐藏滚动条样式沦为无害 no-op）。

## 问题 2：各领域学习资源无法获取（反馈超时）

用户点「获取针对性反馈」一直转圈后失败。curl 复现：feedback 端点 **157s 零字节返回**（curl exit 28 超时）。

**根因链**（`backend/app/agents/content_generator.py` + `api/diagnostics.py`）：
1. `regenerate_for_feedback` 原串行 `for node in target_nodes` 调 LLM，scaffold 取 2 个前置节点 = 2 次串行调用。
2. 上一轮（扩域）加深了 feedback lecture prompt（6 条丰富度要求），单次调用 >60s LLM_TIMEOUT → `max_retries=2` 重试 → 单次最坏 180s，2 次串行超 150s 前端超时。
3. 基线实测：DeepSeek V4 Pro trivial 调用 3.3s，但生成长讲义（1000+ 字）53s——慢在生成长内容，非 API 延迟。

**修复（双管 + 进一步优化）**：
- **并行化**：`regenerate_for_feedback` 串行 `for` 改 `ThreadPoolExecutor`（对齐主生成路径 `_safe_generate` 模式）；worker 内 `_current_overrides.set(overrides)` 重设 ContextVar（Spec B overrides 不跨线程，须 worker 内 re-set）。wall-clock ≈ 单次而非 N×。
- **反馈路径 prompt 减负**：lecture 回退为轻量聚焦版（扩域时加深的 6 条丰富度要求只保留在主生成路径 `_build_generation_prompt`，反馈路径是交互式按需触发、用户等待敏感，应更轻）。
- **限长**：lecture 限 250 字、test 限 200 字（模型原输出 1000-1500 字，限长后 187-248 字）。
- **节点数 2→1**：`select_feedback_nodes` remediate/scaffold 各从 2 节点降为 1（并行不降 wall-clock，瓶颈在单次生成；减半成本与超时风险）。
- **Tavily 与 LLM 并行**：`diagnostics.py` feedback 端点原串行（LLM 再生 + Tavily 联网搜索 +7s），改 Tavily 提交 `ThreadPoolExecutor` 后台先行、主线程并行做 LLM 再生（Tavily 不依赖 LLM/override，无 ContextVar 问题）。

**实测耗时**：scaffold 157s（超时失败）→ 22s（187 字 lecture）。advance（test 类型）仍 ~80s——瓶颈是推理模型生成题目前的隐藏思考（200 字输出花 80s = 2.5 字/s），非 prompt 可解，需换非推理模型。

**坑**：axios 自定义 adapter 不自动生效 `config.timeout`（上一轮已踩，见 memory）；本次后端改动需重启 uvicorn 生效（无 --reload）。

## 问题 3：Agent 协同展示太粗糙（+ 状态推导 bug）

用户反馈原 Agent 协同"太粗糙"，想要"详细告诉用户在做什么、完成情况"。选方案 A（产出概览+进度+实时动作）。

**`useAgentStatus.js` 重构**：
- 新增 `productions`：每 Agent 真实产出（从 store 实数据取：学情检测判分/画像维度、图谱管控节点数+时长、内容生成资源数、内容审核通过/打回+评分）。自适应 interactive 模式（submit 仅跑 学情检测+画像+图谱管控，内容生成/审核按需触发——有产出即展示，无则回落 role 描述）。
- 新增 `currentAction`：运行中取最后日志的 agent + 去时间戳/emoji 的消息。
- 新增 `completedCount`/`pendingCount`。
- **修状态推导 bug**（用户验收发现"0 项完成、图谱管控卡执行中"）：原 `deriveAgentStates` 单靠日志 emoji+关键字正则判 idle/running/done，但 interactive 日志措辞（`🔧 学情检测: 判分 0/10`、`✅ 路径组装完成`）不匹配 demo 的 `开始/✅完成` 正则 → 状态全错。改为**产出覆盖**：有产出即 `done`（ground truth），日志仅保留 running(demo 实时流)/failed/retryCount 探测。
- **修 `pipelineRunning` bug**：原看最后日志是否含"流程结束"，interactive submit 无此标记 → 误判一直运行中。改用 `store.loading && logs.length > 0`（请求 in flight 才运行中）。
- **修 emoji 剥离正则 bug**：`currentAction` 原 `/^[🔧📖📝...]+\s*/` 无 `u` flag，字符类里 emoji 是代理对，匹配时只剥高位代理 → 乱码 `�`。改 `/^[^一-龥a-zA-Z]+/`（剥到首个中文/字母）。

**`StageAgent.vue` 重写**：主视图从"三栏 cockpit（流程节点 + 原始日志流 + 证据面板）"改为「进度行（✅N 完成 · ⏸M 待触发 · ⏳运行中动作）+ 每 Agent 产出概览行（图标+标签+状态徽章+产出摘要）+ 原始日志降为可折叠 `<details>`」。
