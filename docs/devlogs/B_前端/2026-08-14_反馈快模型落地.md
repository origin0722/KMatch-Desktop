# 2026-08-14 反馈快模型落地 — 针对性反馈 22s → ~8s

> 承接 08-13 未决项「反馈仍偏慢（22s）需换非推理模型」。先实测模型耗时矩阵，再落地「反馈专用快模型」设置项（仅反馈请求换快模型，主引擎保持原模型质量）。

## 实测矩阵（同一把 DeepSeek key，后端 get_chat_model + use_llm_overrides 直调）

| 模型 | 讲义类 prompt (scaffold/remediate) | 测试题类 prompt (advance) |
|---|---|---|
| deepseek-v4-pro（现状 .env 默认） | 21.9s | **69.9s** |
| deepseek-v4-flash | **7.8s** | 20.4s |
| deepseek-chat（V3 老版非推理） | **3.7s** | **2.9s** |

- **deepseek-v4-flash 在 api.deepseek.com 真实存在且可用**（.env 同一 key 直调成功）。
- 结论：flash 解决讲义类（最常见反馈路径）到 8s；deepseek-chat 全场景 3-5s 但属 V3 老模型，长内容准确性风险更高（用户在意准确性）。
- .env 无 TAVILY key → 反馈路径无联网耗时，纯 LLM 时间即为反馈耗时。

## 实现（纯前端，后端零改动）

后端 `use_llm_overrides` 本就支持**部分覆写逐字段回退**（`ovr.get("api_key") or settings.LLM_API_KEY`），所以「仅反馈请求换模型」无需后端改动——前端注入 `llm_overrides: { model: "deepseek-v4-flash" }` 即可，key/baseUrl 自动走后端 .env。

- **agentLlm store**（[frontend/src/stores/agentLlm.js](../../../frontend/src/stores/agentLlm.js)）：
  - state 新增 `feedbackModel`，默认 `'deepseek-v4-flash'`（留空 = 跟随引擎模型）。
  - 新增 `buildFeedbackOverrides()` 三态：
    1. feedbackModel 留空 → 返回引擎 overrides（buildOverrides 结果，兼容旧行为）；
    2. 独立配置开 → 全量覆写，仅 model 换快模型；
    3. 独立配置关 → 部分覆写 `{ model }` 仅模型，key/baseUrl 走后端 .env。
  - 新增 `withFeedbackOverrides(body)` 注入 helper；`setProvider` 换非 DeepSeek 厂商时清掉默认 flash（防模型/端点不匹配脚枪，手动设置的快模型不清）。
- **diagnostics.js**：`requestFeedback` 的 `withOverrides` → `withFeedbackOverrides`（唯一调用点，assessment store fetchFeedback）。
- **AgentSettings.vue**：新增「反馈快模型」设置卡，放在独立配置开关块**之外**（不依赖开启独立配置也能生效），info 注明"仅反馈请求生效，留空跟随引擎，换厂商请确认模型属于该厂商"。

## 效果预期

- 用户开箱即得：反馈（讲义类）~22s → ~8s，达标 <10s；advance（测试题）仍 ~20s（flash 推理），需要更快可在设置里改 deepseek-chat（~3s）。
- 主引擎（学情检测/内容生成/审核等）模型不变，质量不受影响。
