## 二、关键决策

- **三合一范围**: 答题+协同+图谱三合一成 LearningSession; 学习资源/数据看板/代码仍独立左侧栏视图 (三者有强叙事连贯, 资源等独立访问更灵活)
- **会话形态**: 纵向会话流, Agent 推动 4 阶段产出卡 (目标→答题→协同→图谱), 最接近"与 Agent 会话"体感, 产出卡避免纯聊天
- **activeStage 派生非独立**: `computed` 从 assessment store 派生 (hasResults/loading/orchestrationLog/phase), 不独立存状态, 避免双源真相。阶段③协同边界: 仅 demo SSE 流期间 (loading && orchestrationLog.length>0); interactive 判分 loading 仍属阶段②答题卡
- **主从分屏非 VSCode 平等容器**: YAGNI; VSCode 平等容器组超出学习场景, 自研布局引擎代价过大。主从 (会话流主体 + 至多 1 右侧分屏) 足够
- **分屏=布局模式不复制组件**: 左侧栏视图组件原样在分屏右半 v-show 渲染, 零状态同步; 与 S6 治理一致 (v-show 常驻, G6/Monaco 不销毁)
- **不引布局库**: Vue 无成熟 mosaic; 与 --km-* token/Monaco 常驻冲突; 赛题验收风险
- **AI 助手双向联动 UI 独立**: 会话产出注入助手 system prompt 上下文, 助手可被追问; 不并入会话流 (专业知识获取更适合"联动但独立")
- **AnySearch 留独立项**: 本次只做前端三合一, 专业搜索后端工具单独立项

## 三、赛题功能影响

- **赛题(4)② 多智能体协同可视化**: Agent cockpit 从独立视图收进会话流阶段③, 答题→协同→图谱叙事连贯, 演示力增强
- **赛题场景一全流程闭环**: 学情画像→图谱组装→资源生成→审核→反馈, 在会话流里按阶段推进可见
- **零功能回归**: 答题/判分/反馈/图谱/协同逻辑一字未改 (搬运用), store API 不变; 双向联动是增量
