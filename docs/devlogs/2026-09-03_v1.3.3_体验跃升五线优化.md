## 背景

用户提出四个方向: 提升内容生成等待体验、优化知识/项目图谱、减少 AI 味, 外加规划期追加的
「AI 助手回答格式」。约束: 不破坏任何功能行为契约。批 0 先把工作区未提交的 AI 助手 UX
第二批 (停止角标版本级/_systemFeed/编辑重发守卫) 验证并提交为隔离基线。

## 批 2 · 等待优化感知层

- 新增 `backend/app/api/sse.py`: 队列桥接 SSE 响应 (`sse_stream_response`)——worker 线程跑
  重活, `emit(event, data)` 经队列喂同步生成器; 生成器 `q.get` 15s 心跳, 同时解决浏览器
  60s 看门狗误杀长静默流与 Electron IPC 长静默无反馈两个对向问题; 客户端断开置取消事件。
- `/submit/stream`、`/feedback/stream`、`/report/stream` 三个流式端点复用 `_run_submit/
  _run_feedback/_report_compute` 单一实现 (REST 路由抽 `_report_ctx/_report_compute` 两段,
  校验段保持 HTTP 语义, stream 版缓存命中直接同步返 JSON)。旧 REST 保留, 前端按 e.status
  404 降级。
- content_generator: `pool.map` → submit+as_completed, 每段资源完成回调
  `progress_cb(done, total, node, ctype)`; `cancel_check` 检查点提前收摊 (已完成保留, 未跑
  记「已取消」)。`with_state_overrides` 装饰器扩展透传 kwargs。
- 前端: `postSseJson` promise 化 POST-SSE 壳 (双环境); assessment store 三动作 stream-first
  + REST 兜底 + `progressMessage`/`cancelWait`; StageQuiz 等待区接真实进度文案 + 停止按钮,
  硬编码猜测时长 ("最长约 1/5 分钟") 全部移除。

## 批 3 · 真实提速

- 裁判并行化: quality_judge 幻判/难度判 `_parallel_invoke` (JUDGE_CONCURRENCY=4),
  原 ≤10 次串行 LLM 是 report 补跑 wall-clock 大头; prompt 预构建在主线程。
- 节点级再生缓存: 打回时只重生成 `issues[].source_node` 点名节点 (15 次→3-6 次),
  未点名沿用既有资源; 点名缺失保守全量 (行为不变); +4 单测。
- 判分可选快模型: `buildGradingOverrides`/`withGradingOverrides` (默认关, 设置页 opt-in)。
- 耗时打点: 生成/审核/裁判 elapsed_ms 入 orchestration_log+logger。
- 「报告后台化」经批 2 SSE+停止等待+缓存秒开已达成, 不再另建后台任务层 (避免过度建设)。

## 批 4 · 图谱正确性与性能

- **P0 修复 stale 检测**: 原 `markStale` 比较 `sourcePath(项目根) === 事件 path(具体文件)`
  永假 → 过期横幅从不出现, 用户会按旧行号跳错代码。现 setGraph 记录 `coveredModules`,
  按「改动文件推导模块 ∈ 覆盖集」判定 (watcher 与 listDirectory 均为工作区相对路径, 同源可
  精确匹配); +3 测试含修复回归用例。
- 解析提速: 并行读文件 (Promise.all) / `parse_module_source(return_tree=True)` 复用 AST 免
  第二次 parse / Jedi infer 结果缓存 + 300 次上限 (超限走语法名回退) / 响应裁 `source_code`
  (`with_source` 可选, 前端只存不读已核实)。
- `GET /prerequisites/batch` → `POST /prerequisites/batch` (UNWIND 单查询; embedded 同实现),
  图谱视图 20 RTT → 1; 前端 404 回退逐节点。
- KG 高亮走 `updateNodeData/updateEdgeData + draw()` 增量 (不重排, 保留拖拽位置), 图元数
  变化才回退全量重建; PG 搜索 200ms 防抖 (原每击键 destroy+dagre 全排)。

## 追记 · v1.3.4 热修 (2026-09-03)

用户真机反馈: 答题点「提交」报 `An object could not be cloned.`

- **根因**: 批 2 流式优先改造后, submit/feedback 载荷经 `postSseJson` → `window.api.http.stream` →
  `ipcRenderer.invoke` 走**结构化克隆**, 而载荷里的 `styleQuiz/demographics/profile` 是 Vue
  深层响应式 **Proxy**(克隆算法不支持) → 直接抛错。旧 REST 路径经 axios transformRequest 先
  stringify 成字符串故从未暴露; demo 流载荷全为基本类型亦不受影响。vitest 全 mock 传输层未覆盖。
- **修复**: `postSseJson` 入口单点 `JSON.parse(JSON.stringify(body ?? {}))` (fetch 分支本就
  stringify 无害); IPC 全调用面审计确认仅此两流受累 (chat 传输层与设置页直调载荷均为字面量)。
- **回归**: +`frontend/src/__tests__/sse-transport.test.js` 3 测 — 真实 `reactive()` 载荷
  mock IPC 捕获后必须过 `structuredClone` 且内容无损。
- 版本 1.3.4, 重打 sidecar + 安装包, Release v1.3.4 替换受影响的 v1.3.3 分发。
