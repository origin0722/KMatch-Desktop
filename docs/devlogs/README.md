# KMatch·知链 — 开发日志目录

> 单人全栈开发（2026/06/20 起由 3 人协作转为单人）。开发日志按端分类维护，历史 A_后端/B_前端/C_数据 目录保留。
> Desktop 阶段日志见 [Desktop_阶段总览.md](Desktop_阶段总览.md)；每次开发会话结束后在对应目录下新建 `YYYY-MM-DD_主题.md`。

---

## 目录结构

```
docs/devlogs/
├── README.md                    ← 本文件
├── A_后端/                       ← 成员 A — 后端负责人
│   └── YYYY-MM-DD_主题.md
├── B_前端/                       ← 成员 B — 前端负责人
│   └── YYYY-MM-DD_主题.md
└── C_数据/                       ← 成员 C — 数据与质量负责人
    └── YYYY-MM-DD_主题.md
```

## 日志命名规范

```
YYYY-MM-DD_简短主题.md
```
示例：`2026-06-16_前置准备与环境搭建.md`

## 日志内容模板

每个日志文件应包含以下部分：

```markdown
# YYYY-MM-DD — 标题

**参与成员**: 自己
**会话目标**: 今天要完成什么

## 一、产出

| 产出 | 文件 | 说明 |
|:---|:---|:---|

## 二、遇到的 BUG（参见 docs/BUG决策日志.md）

| BUG 编号 | 简述 | 解决状态 |
|:---|:---|:---|

## 三、环境变更

- 装了什么新依赖
- 改了什么配置

## 四、待办

- [ ] 下次要做什么
```

## BUG 日志

**BUG 决策日志是共享的**，放在 `docs/BUG决策日志.md`。

遇到技术问题 → 在 BUG 决策日志中创建一个新条目 → 在自己日志中引用编号。

## 同步提醒

- 每天结束前 `git pull` → 写日志 → `git add` → `git commit` → `git push`
- 日志冲突：谁后提交谁手动合并（日志内容独立，通常无冲突）
