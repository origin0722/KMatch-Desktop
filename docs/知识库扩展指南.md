# 知识库扩展指南

> KMatch 知识库 (知识节点 + 题库) 三种扩展方式：API / 脚本 / 手动编辑 JSON。
> 适用场景：新增知识点、新增题目、引入新领域 (如机器学习)。

## 数据模型速览

### 知识节点 (`KnowledgeNode`)

存于 `data/knowledge_base/member_*/PY-xxx_yyy_topic.json`（顶层数组，一文件多节点）。

| 字段 | 类型 | 必填 | 约束 |
|:---|:---|:---:|:---|
| `id` | string | ✅ | `^[A-Z]{2}-\d{3}$`，如 `PY-092`、`ML-001` |
| `name` | string | ✅ | 2-60 字符 |
| `difficulty` | int | ✅ | 1-5 |
| `category` | string | ✅ | enum: 基础语法/数据结构与算法/面向对象编程/Python进阶/常用库与工具/项目实战 |
| `summary` | string | ✅ | 30-500 字符 |
| `prerequisites` | string[] | ✅ | 前置节点 id 列表，空数组=入口 |
| `key_points` | string[] | ✅ | 3-8 条 |
| `practice_questions` | object[] | ✅ | 至少 1 道（存档用，运行时出题走题库） |
| `common_mistakes` | string[] | 建议 | 常见误区，5 处 Agent 消费 |
| `tags` | string[] | 否 | 1-6 个 |
| `estimated_minutes` | int | 否 | 5-240 |

> 注：`common_mistakes` 在 schema.json 非必填，但 `validate_data.py` 强烈建议补全（缺失仅 warning）。

### 题目 (`Question`)

存于 `data/knowledge_base/questions/<node_id>.json`（顶层数组，一文件多题）。

| 字段 | 类型 | 必填 | 约束 |
|:---|:---|:---:|:---|
| `qid` | string | ✅ | `^Q-[A-Z]{2}\d{3}-\d{3}$`，如 `Q-PY001-004` |
| `source_node_id` | string | ✅ | 所属知识点 id，须已存在 |
| `type` | string | ✅ | choice / fill / code |
| `question` | string | ✅ | ≥5 字符 |
| `options` | string[] | choice 必填 | 2-6 个 |
| `answer` | string | ✅ | choice=字母，fill=关键词，code=代码 |
| `difficulty` | int | ✅ | 1-5 |
| `hint` / `explanation` | string | 否 | |

## 方式一：API（推荐，可编程/可对接前端管理页）

后端 CRUD API，**JSON 为源，写后同步 Neo4j**。路由前缀 `/api/kb`。

### 知识节点

```bash
# 创建 (id 自动递增, 或手动指定)
curl -X POST http://localhost:8000/api/kb/nodes \
  -H "Content-Type: application/json" \
  -d '{
    "name": "列表推导式", "difficulty": 3, "category": "基础语法",
    "summary": "列表推导式是 Python 中简洁创建列表的语法糖...(≥30字符)",
    "prerequisites": ["PY-001"], "key_points": ["要点1","要点2","要点3"],
    "practice_questions": [{"type":"choice","question":"q","options":["A","B"],"answer":"A"}],
    "common_mistakes": ["误用"], "tags": ["进阶"], "estimated_minutes": 30
  }'
# → {"node": {"id": "PY-093", ...}, "warnings": []}

# 查询
curl http://localhost:8000/api/kb/nodes/PY-093

# 更新 (全量, prerequisites 变化会重建 REQUIRES 关系)
curl -X PUT http://localhost:8000/api/kb/nodes/PY-093 -H "Content-Type: application/json" -d '{...}'

# 删除 (?cascade=true 连带删其题目)
curl -X DELETE "http://localhost:8000/api/kb/nodes/PY-093?cascade=true"
```

### 题目

```bash
# 创建 (qid 自动递增, source_node_id 须存在)
curl -X POST http://localhost:8000/api/kb/questions \
  -H "Content-Type: application/json" \
  -d '{
    "source_node_id": "PY-093", "type": "choice",
    "question": "下列哪个是合法的列表推导式？",
    "options": ["A. [x for x in range(10)]", "B. ..."],
    "answer": "A", "difficulty": 3
  }'
# → {"question": {"qid": "Q-PY093-001", ...}, "warnings": []}

curl http://localhost:8000/api/kb/questions/Q-PY093-001
curl -X PUT http://localhost:8000/api/kb/questions/Q-PY093-001 -d '{...}'
curl -X DELETE http://localhost:8000/api/kb/questions/Q-PY093-001
```

### 错误码

| 码 | 含义 |
|:---|:---|
| 200 | 成功（创建/查询/更新/删除） |
| 400 | 校验失败（字段不合规），`detail.errors` 为错误列表 |
| 404 | 节点/题目不存在 |
| 409 | id/qid 已存在（创建时） |
| 503 | Neo4j 未就绪 |

### 同步语义

- 写操作先改 **JSON 文件**（真相源），成功后同步单节点/题目到 Neo4j。
- Neo4j 同步失败**不回滚 JSON**，响应 `warnings` 提示，下次 `import_knowledge_base.py` 重导可修复。
- 节点内容变更后自动重算 embedding（向量检索用）。

## 方式二：脚本（批量/初始化）

适合大批量导入（如引入整个新领域）。

```bash
cd backend

# 1. 校验数据格式
python scripts/validate_data.py ../data/knowledge_base/

# 2. (可选) LLM 批量生成 common_mistakes
python scripts/generate_common_mistakes.py ../data/knowledge_base/

# 3. (可选) LLM 批量生成题目到 questions/
python scripts/generate_practice_questions.py ../data/knowledge_base/

# 4. 全量导入 Neo4j (清空重建: 清旧→建节点→建关系→建题目→建向量索引)
python scripts/import_knowledge_base.py ../data/knowledge_base/
```

> `import_knowledge_base.py` 是**全量清空再建**，会删除现有 KnowledgeNode/Question 后重建。
> 增量管理请用 API（方式一）；脚本用于初始化或修复。

## 方式三：手动编辑 JSON

适合小规模调整或离线编辑。

1. 编辑 `data/knowledge_base/member_*/` 下的节点 JSON，或 `questions/<node_id>.json` 题目。
2. `python scripts/validate_data.py ../data/knowledge_base/` 校验。
3. `python scripts/import_knowledge_base.py ../data/knowledge_base/` 同步到 Neo4j。

**节点 JSON 格式**（一文件多节点，顶层数组）：
```json
[
  {
    "id": "PY-093", "name": "列表推导式", "difficulty": 3, "category": "基础语法",
    "summary": "...(≥30字符)", "prerequisites": ["PY-001"],
    "key_points": ["...", "...", "..."],
    "practice_questions": [{"type":"choice","question":"q","options":["A","B"],"answer":"A"}],
    "common_mistakes": ["..."], "tags": ["进阶"], "estimated_minutes": 30
  }
]
```

## 引入新领域（如机器学习）

1. **规划节点**：确定 ML 知识点 id 前缀（如 `ML-001`~`ML-050`），按依赖关系排 prerequisites。
2. **录入数据**：用方式一 API 逐个创建（id 自动从 `ML-001` 起），或方式二/三 批量。
3. **生成题目**：`generate_practice_questions.py` 会按节点生成 choice/fill/code 题到 `questions/ML-xxx.json`。
4. **校验+导入**：`validate_data.py` → `import_knowledge_base.py`。
5. **验证**：`POST /api/diagnostics/assess` 用 ML 方向目标测评，确认出题/路径/内容全链路走通。

> 新领域无需改代码：节点 id 正则 `^[A-Z]{2}-\d{3}$` 支持任意 2 字母前缀，引擎对领域无感。
> Agent prompt 含 "Python" 字样为文案占位，多领域演示时可按需泛化（后续优化项）。
