# 数据合规与隐私保护说明

> 赛题 XH-202630 作品要求 (5) 数据合规性与伦理规范 对应文档
> 版本: v1.4.0 | 日期: 2026/09/03（v1.0 于 2026/08/16 初版；v1.4.0 更新存储口径与数据规模）

## 一、总体架构：本地化优先

KMatch·知链 以 **Electron 桌面应用** 形态交付（非 Web 服务），数据链路设计遵循"本地优先"原则：

| 数据类别 | 存储位置 | 是否离开本机 |
|:---|:---|:---:|
| 用户画像（学情测评结果） | 本地图存储（默认嵌入式 `data/local/`，可选 Neo4j）+ 前端 Pinia 内存态 | ❌ 否 |
| 测评答题记录 / 会话数据 | 后端进程内存（LRU 会话缓存，重启即清） | ❌ 否 |
| 学习资源（讲义/实操/测试题） | 本地图存储（嵌入式/可选 Neo4j）+ 前端 localStorage | ❌ 否 |
| 项目代码图谱 | 本地图存储（嵌入式/可选 Neo4j） | ❌ 否 |
| 用户工作区文件 | 本地文件系统（用户自选目录） | ❌ 否 |
| API 密钥（LLM/Tavily） | 本地 `.env` 文件 + 应用内设置（不上传） | ❌ 否 |

**唯一离开本机的数据**：LLM 推理调用（见第三节）。

> 存储形态说明：安装包默认**进程内嵌入式存储**（`EmbeddedGraphStore`，可变数据落应用数据目录 `data/local/`，见 ADR-0008），端用户免 Docker；Neo4j 仅为可选后端（`GRAPH_STORE=neo4j`）。两类后端均只在本机运行，数据不离开本机。

## 二、测试数据合规：全量合成，无真实个人数据

赛题要求 (5) 原文："**若使用真实培训、测试或学情数据**，需符合法律法规及隐私保护要求"。

本系统的全部测试数据为**人工构造的合成数据**，不含任何真实个人数据：

- **12 份画像文件**（`data/user_profiles/`，10 组差异化合成画像 + schema + 模板）：虚构人物（如"零基础的小王"、"转行做数据分析的老张"），人口学字段（年龄段/学历/专业）为教学适配设计的典型组合，不指向任何真实自然人；配套 `profile_schema.json` 显式声明字段语义。
- **292 个知识节点**（6 域 + 动态领域）：领域专业知识，无个人属性。
- **163 个题库文件 / 423 题**：Python 及各领域教学题目，无个人属性。
- **演示工作区项目**：内置示例代码（爬虫/Todo 后端），无真实业务数据。

**结论**：因不使用真实培训/测试/学情数据，赛题 (5) 的触发条件（"若使用真实数据"）不成立；本说明同时给出下述工程措施，确保未来接入真实数据时合规路径清晰。

## 三、LLM 调用的数据传输边界

系统调用外部大模型 API（DeepSeek，OpenAI 兼容接口）时，传输内容与边界如下：

**会传输的内容**（推理必需）：
- 测评题目文本、用户答案文本（用于判分）
- 知识图谱节点事实（summary/key_points，公开领域知识）
- 项目代码片段（场景二代码审查/测试，仅用户自己打开的工作区）

**不传输的内容**：
- 用户姓名、联系方式等直接标识符（画像中本就不采集真实身份信息）
- API 密钥之外的本地配置
- 用户文件系统中未被主动打开的文件

**用户可控性**：
- API Key 由用户自行配置（设置页 / `.env`），可随时更换或清空；不配 Key 时相应功能明确降级提示，不静默外传。
- 独立裁判（JUDGE_LLM_*）可配置为不同厂商，评测链路与生成链路可隔离。

## 四、用户数据的知情与清除

- **知情**：本说明随源码仓库交付，部署说明（README）中明示 LLM 调用边界。
- **可清除**：
  - 学习画像与会话：默认嵌入式形态删除应用数据目录 `data/local/` 即全量删除；可选 Neo4j 形态下 `docker-compose down -v` 清空；
  - 前端残留（localStorage 的会话 id / 偏好设置）：应用内可清除历史记录（AI 助手设置页"清历史"），或直接清除应用数据目录；
  - 无任何远端副本需要回收（系统不运营服务端）。

## 五、伦理规范

- 生成内容经内容审核 Agent 把关（事实性/幻觉四维度），并支持独立裁判（LLM-as-Judge）复核，避免错误教学内容误导学习者。
- 启发式导学模式以引导替代直接给答案，避免代写作业类滥用。
- 测试画像覆盖多元背景（零基础/转行/高中/跨语言等），适配逻辑按能力而非人群标签分层，不含歧视性差异化定价或排斥性设计。

## 六、后续接入真实数据的合规路径（预留）

若未来在真实培训场景部署，需补充：

1. **脱敏管道**：画像字段入库前剥离直接标识符，人口学字段做泛化（如年龄段代替出生年月）；
2. **知情同意**：首次测评前展示数据用途说明并获得用户确认；
3. **传输加密**：若改为服务端部署，全链路 HTTPS + Neo4j 认证强化（当前桌面形态下数据不出本机，风险面即本机）；
4. **日志规范**：运维日志不含答题内容明文（当前本地开发日志仅记录统计量与错误堆栈）。

## 七、交互日志脱敏规则表

本表对应后端交互日志脱敏组件（`backend/app/utils/redaction.py`）。当 `should_redact()` 判定为真时，`run_store` 在落盘 `run.json` / `events.jsonl` 前，会对 `request` 内**键名命中**敏感清单的字段做打码，保证运行历史（复盘/续跑）不含答题原文、实操描述与直接/间接标识符。

| 敏感字段（键名，大小写不敏感子串匹配） | 脱敏规则 |
|:---|:---|
| `answers` | 答题原文打码（判分/反馈落盘的作答内容） |
| `answer` / `explanation` | 题目正确答案与解析打码 |
| `practical_evidence` | 实操能力证据（代码测试通过率等描述）打码 |
| `learner_key` | 学习者稳定标识（跨次画像档案键）打码 |
| `api_key` | LLM/Tavily 等 API 密钥打码 |
| `email` | 邮箱打码 |
| `phone` | 手机号打码 |
| `name` | 姓名（含 `userName`/`student_name` 等派生键）打码 |

**打码算法（`mask_secret`）**：标量保留首 4 尾 4、中间以 `*` 替换，**长度不变**；超短值（≤4 字符）全量打码，短串（4<n≤8）退化为各保留首尾 2 位。命中键名的值无论为标量、dict 还是 list 一律打码，不泄露原文。

**开关**：环境变量 `PRIVACY_REDACT_INTERACTION_LOGS`。

- **默认关闭（`"0"`）**：本地单机 + **全合成测试数据**场景（本作品当前形态）无真实个人信息，脱敏无收益且会降低复盘/联调可读性，故默认**不开启**，保证运行历史原样可读、行为与未接入脱敏时完全一致。
- **接入真实培训/学情数据前必须开启（置 `"1"`）**：此时落盘的 `request` 内答题原文、实操证据、学习者标识、密钥、邮箱/手机/姓名等一律打码。

**最小化采集建议**：接入真实数据后，除开启脱敏外，应进一步遵循第五节合规路径——画像/日志字段入库前剥离直接标识符，人口学字段做泛化（年龄段代替出生年月/精确年龄），首次测评前展示数据用途说明，并在无需该类字段时**不采集**。脱敏是兜底防线，最小化采集才是治本。
