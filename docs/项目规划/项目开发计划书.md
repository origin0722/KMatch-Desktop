## 一、项目概述

### 1.1 项目背景

当前大模型在垂直教育领域面临三大核心困境：其一，生成专业内容时极易产生"幻觉"，输出不符合行业规范的知识；其二，"个性化适配"与"专业质量把控"在单一模型架构下难以调和；其三，传统"千人一面"的静态资源分发模式无法满足学习者的差异化需求。本赛题（XH-202630）要求参赛者构建多智能体协同决策系统，攻克大模型在垂直领域落地的核心技术难关。

### 1.2 项目目标

设计并开发 **"KMatch·知链"**——一个以四层知识图谱为共享事实底座、以多智能体协同决策为核心引擎的个性化学习平台。系统面向计算机学科领域，覆盖"无项目的定向技能训练"与"已有项目的二次开发与能力提升"两类核心场景，实现"学情画像构建→多智能体协同调度→领域知识个性化生成→交互反馈→动态决策更新"的全流程闭环。

### 1.3 核心创新点

1. **知识图谱约束的多Agent协同架构**：四层知识图谱（领域元知识层/项目框架层/代码实体层/演化扩展层）作为所有Agent的唯一事实底座，从架构层面固化知识边界，系统性消除大模型"幻觉"。
2. **多Agent"辩论与交叉验证"机制**：生成Agent提交产出后，审核Agent对照图谱事实逐条校验，不一致即打回修改并附带溯源说明，通过多轮博弈确保知识高保真。
3. **脚手架式阶梯引导机制**：将二次开发引导分为5级粒度，根据用户能力水平和尝试次数动态匹配，平衡"训练有效性"与"用户体验"。
4. **核心框架+领域插件架构**：核心层与领域无关，切换领域仅需更换领域插件，支撑跨领域快速迁移。

## 二、系统架构概要

### 2.1 整体架构

系统采用三层架构，从上到下依次为前端展示层、后端服务层、数据持久层。

**前端展示层（Vue3 + Element Plus + AntV G6）**

| 页面模块 | 功能说明 | 核心技术 |
|:---|---|:---:|
| 用户测评页 | 学情测评问卷、答题交互、用户画像报告展示（雷达图+能力分值） | Element Plus |
| 图谱可视化页 | 四层知识图谱交互式渲染、节点点击详情、掌握状态着色 | AntV G6 |
| 学习资源页 | 分层讲义/实操指南/分阶测试题分区展示、排版美化、在线作答 | Element Plus |
| Agent协同可视化页 | 多Agent流转过程动画、Agent实时状态面板、运行日志 | WebSocket + CSS动画 |
| 数据看板 | 知识盲区热力图、资源难度匹配曲线、个性化学习路径规划图 | ECharts / AntV G6 |

前后端通过 **HTTP/WebSocket** 通信。

**后端服务层（FastAPI + LangGraph）**

后端核心由 **主控调度Agent（LangGraph）** 统一编排，下辖五个职责明确的子Agent：

| 后端模块 | 职责 |
|:---|---|
| **主控调度Agent** | 全局状态管理、流程编排、冲突裁决、循环控制 |
| **学情检测Agent** | 理论+实操+学习风格三维测评，输出用户能力画像 |
| **知识图谱管控Agent** | 无项目：组装学习路径图谱；有项目：解析代码生成项目图谱 |
| **领域知识生成Agent** | 基于图谱和画像生成个性化学习资源（讲义/实操指南/测试题） |
| **内容审核Agent** | 对照图谱事实校验生成内容，幻觉检测与知识溯源 |
| **代码测试Agent** | 自动生成测试用例并执行，反向标注图谱风险节点 |

所有Agent共享同一个 **大模型API适配层（OpenAI兼容接口）**，对接DeepSeek/通义千问等模型。

**数据持久层**

| 存储系统 | 存储内容 | 技术选型 |
|:---|---|:---:|
| **四层知识图谱** | 领域元知识层（静态）/项目框架层/代码实体层/演化扩展层（动态） | Neo4j |
| **用户数据库** | 用户画像、学习记录、交互日志 | SQLite |
| **文件存储** | 学习资源文件、测试数据、项目代码 | 本地文件系统 |

**数据流转关系**：所有Agent的输入输出均锚定在四层知识图谱上——生成Agent引用图谱节点、审核Agent对比图谱事实、测试Agent基于图谱接口定义、学情Agent将用户掌握状态标注回图谱节点。图谱是系统唯一的"共享事实底座"。

### 2.2 核心业务流程

#### 场景一：无项目的定向技能训练

**Step 1 — 学情诊断**：用户输入学习需求，学情检测Agent完成"理论测试 + 实操测评 + 学习风格分析"三维评测，输出结构化用户能力画像。

**Step 2 — 图谱组装**：主控调度Agent触发知识图谱管控Agent，根据用户画像从领域元知识库中抽取对应知识点节点，按照前置依赖关系拓扑排序，组装成渐进式个性化学习路径图谱。

**Step 3 — 图谱审核**：内容审核Agent校验图谱的节点正确性和路径合理性，确认无错误后进入生成环节；发现问题则打回图谱管控Agent修正。

**Step 4 — 资源生成**：领域知识生成Agent基于审核通过的图谱和用户画像，生成三种形态的个性化学习资源——分层讲义（理论讲解）、阶梯式实操指南（动手实践）、分阶测试题（巩固练习）。每段内容标注所引用的图谱节点ID。

**Step 5 — 内容审核**：内容审核Agent对照图谱事实节点逐条校验生成内容，发现不一致（幻觉）即打回生成Agent修改并附带溯源说明；通过多轮"生成→校验→修正"的博弈确保知识高保真。

**Step 6 — 交付学习**：通过审核的资源交付给用户，用户完成学习后进行答题测试。

**Step 7 — 动态迭代**：学情检测Agent根据答题正确率更新图谱节点掌握状态，主控调度Agent决策后续策略——正确率≥80%则进入下一节点或生成进阶挑战；正确率50%-80%则生成降维解释（换角度重新讲解）；正确率<50%则标记为"困难"节点，补充前置基础知识后再试。

#### 场景二：已有项目的二次开发与能力提升

**Step 1 — 双维度测评**：用户上传项目代码并描述二次开发目标，学情检测Agent同时测评两方面的能力——①对项目现有技术栈的掌握程度；②开发目标相关的知识储备。

**Step 2 — 项目图谱生成**：知识图谱管控Agent对项目代码进行静态分析（AST语法树解析），自动提取函数、类、调用关系，生成"项目框架层+代码实体层"图谱初稿，并标注与开发目标相关的接口、模块、依赖节点。

**Step 3 — 图谱校验**：内容审核Agent将项目图谱初稿对照领域元知识库做比对校验，修正错误的依赖关系、标注不符合行业规范的代码，形成完整的项目知识图谱。

**Step 4 — 分层引导**：领域知识生成Agent基于用户水平输出两类内容——①分层项目解读（从宏观架构到微观代码）；②阶梯式二次开发引导（5级引导粒度，从方向提示到关键代码片段，绝不直接给出完整可运行代码）。

**Step 5 — 用户自主修改**：用户根据引导自主完成代码修改，培养独立开发能力。

**Step 6 — 两级校验**：用户提交修改后的代码后进入检查环节——①内容审核Agent进行代码审查（对照领域规范检查逻辑错误、代码规范、安全隐患）；②代码测试Agent自动生成单元测试用例并执行，输出通过率与覆盖率报告。

**Step 7 — 闭环迭代**：校验未通过则由主控调度Agent打回生成Agent重新引导修改，形成"修改→审查→测试→再修改"的迭代循环；校验通过则更新演化扩展层图谱，记录本次开发沉淀的新知识节点，完成闭环。
