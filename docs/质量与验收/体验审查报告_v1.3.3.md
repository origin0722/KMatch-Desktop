## 一、P0 — 正确性 / 体验硬伤（本轮必修）

### P0-1 项目图谱 stale 检测失效 → 按旧行号跳错代码
- `frontend/src/stores/projectGraph.js:125-131` `markStale(path)` 比较 `g.sourcePath === path`，
  而 `sourcePath` 在自动解析时被设为**项目根**（projectGraph.js:168 `setGraph(result, ws.root)`），
  workspace 文件监听事件给出的是**具体文件路径** → 全等比较永假，过期横幅从不出现。
- 后果：文件改动后用户从图谱/助手实体列表点击跳转，Monaco 按旧行号 reveal（MonacoEditor.vue:141-175），
  可能落到错误的代码位置。stale 时"禁用跳转"的既有设计（AssistantPanel.vue:117-127）因此失效。

### P0-2 机器标记泄漏进用户可见正文
- `[已心算验证]`：提示词要求标注进正文（backend/app/agents/content_generator.py:152、
  data/prompts/04_content_generator_agent.txt:54,112），前端零剥离 → 讲义/测试题原文带着标记渲染。
- `[ref: PY-012.key_points[2]]`：溯源标记写入 markdown（00_shared_contracts.md:19 定义），
  前端零剥离（全仓 grep 无任何 strip 逻辑）→ Learning 页与学习资源直出。
- 溯源机制本身有结构化承载（`source_nodes` 字段，reviewer.py:114 硬规则校验），正文内联标记是冗余暴露。

### P0-3 语义搜索失败静默无提示
- `frontend/src/views/KnowledgeGraph.vue:948-951`：`/api/graph/search` 在 embedding 未配置时返回 503，
  catch 分支无任何 UI 提示 → 核心搜索功能"看起来坏了"。无名称子串降级检索。

### P0-4 interactive 主链等待黑盒：无进度、不可取消
- submit/feedback/report 全是阻塞 axios（assessment.js:266-314/377-417/426-447），无 SSE 等价物；
  内容生成 15 次 LLM 调用对前端完全黑盒（demo SSE 也只在整节点结束时报一条 progress，
  api/diagnostics.py:574-593）→ 最长 1-2 分钟+ 的 content_generator 节点期间零反馈。
- demo SSE 无 AbortSignal（api/diagnostics.js:281-327,361-379），后端无取消端点；run 一旦启动只能等完或超时。
- 等待文案为硬编码猜测（StageQuiz.vue:127-128 "最长约 1 分钟/5 分钟"），与真实进度无关。

### P0-5 SSE 长静默两难：浏览器误杀 / Electron 静默挂起
- 浏览器 dev 回退：60s 无数据看门狗断流（api/diagnostics.js:304-310）——恰好掐死最耗时的
  content_generator 节点（期间无任何事件）→ 误杀仍在正常生成的流。
- Electron IPC SSE 路径（api/diagnostics.js:361-379）：无看门狗也无心跳 → 长静默期既无反馈也无法发现真断流。
- 两个方向都错；根因是"节点内无事件"。修法：资源粒度进度事件（第 2 批）+ 心跳/看门狗对齐。

## 二、P1 — 性能 / 可感知卡点（本轮修）

### P1-6 独立裁判逐条串行
- `backend/app/agents/quality_judge.py:150-173,216-229`：幻觉判+难度判对 ≤5 资源为串行 for 循环
  （最多 10 次串行 LLM），且同步阻塞 report 响应（api/learning.py:161）。并行基元已具备
  （llm.py:269-288 safe_llm_call 跨线程 ContextVar + content_generator.py:329-337 ThreadPool 样板）。

### P1-7 报告补跑 = 第二次全量生成，同步阻塞 300s
- 进入 Dashboard 触发 `POST /api/learning/report`（Dashboard.vue:863 → api/learning.py:172-270）：
  graph_controller → content_generator(15 次调用) → reviewer →(打回再生 ≤2 轮) → 裁判，
  全部同步在请求线程内，前端 axios 300s 等待。已有幂等缓存（api/learning.py:200-252）但首访仍全额阻塞。

### P1-8 内容生成 wall-clock 大头：15 次长文调用 + 打回整轮重来
- max_tokens=16384（config.py:36），5 节点×3 类型并发 5 实测 137s（content_generator.py:326-337）；
  reviewer 打回后**整轮 15 次重生成**（orchestrator.py:87-102 max_retries=3），无节点级缓存免掉未 flagged 部分。

### P1-9 项目图谱搜索击键级全量重建
- `frontend/src/views/ProjectGraphView.vue:112` `@input="rebuildGraph"` → destroy+new Graph+dagre
  全量重排（:914-917），数百节点时每次按键卡顿。

### P1-10 大项目解析四处耗时点
- 串行读文件（api/project.js:25-31 for..of readFile）；同一源码两次 ast.parse（ast_parser.py:57,216）；
  Jedi 每个 raw_call 一次 infer 无缓存无上限（jedi_resolver.py:124）；且 Jedi 单文件模式跨模块调用
  永不解析（loader.py:93-95）；响应携带全部函数 source_code（api/project.py:432，前端只存不读，
  project.js:117 透传无消费点）。

### P1-11 知识图谱前置依赖 N+1
- `KnowledgeGraph.vue:659-685` 每节点 1 个 `GET /api/graph/prerequisites/{id}` 并行发起，
  每次 displayGraph 变化（含历史切换 deep watch :1169-1179）重拉 → 打开 20 节点路径 = 20 RTT。

### P1-12 判分 45s 零重试压在交互关键路径
- `backend/app/agents/diagnostics.py:113-116`：`get_chat_model(max_retries=0, timeout=45)`（注释自证
  "前端已等待 2 分钟"的治理权衡），外层 90s wait_for（api/diagnostics.py:674-681）；慢端点直接 504。
  可选快模型分流可解（默认关，设置页 opt-in）。

### P1-13 query_project_graph 全量 relations 塞 LLM 上下文
- `frontend/src/stores/chat.js:1115`：实体只留 name/kind，但 relations **全量**进上下文 → token 成本与
  截断风险。后端实体↔知识点关联能力已有（engine.py:808-820、embedded.py:871-882）但前端无入口。

### P1-14 图谱信息设计：颜色双编码冲突 + 动态领域无色板
- KG 节点填充色=难度（KnowledgeGraph.vue:795），但 PathFinder chip=分类色（PathFinderModal.vue:21）、
  分类分布=分类色（KG.vue:275）→ 同一"节点颜色"三种含义。
- 「动态领域」70 节点（_manual_nodes.json，实测全库 292 节点/12 分类）不在色板与筛选器中
  （KG.vue:423-436,530-535）→ 灰色不可筛。

### P1-15 PathFinder 查了路径还得手动在图里找
- PathFinderModal.vue:58-87 结果仅 chip 列表，无"在图中高亮+fitView"（dimmed 机制已有，KG.vue:731-743）。

  工具结果以 `[工具返回]` user 消息回喂（chat.js:1341）携带原始字段格式；
- 流式渲染：每增量全量重渲染（MarkdownViewer.vue:97-103），未闭合代码围栏排版跳变，
  长回答多代码块时 Monaco colorize 重复异步执行（:108-130）。表格/引用样式已齐（:287-307，无需动）。

## 四、超时链贯通核实（无断裂，两处认知修正）

| 层 | 值 | 出处 |
|:---|:---|:---|
| LLM 单调用 | 60s（重试 2）；判分特例 45s/0 重试 | config.py:54 / diagnostics.py:113-116 |
| axios 默认 | 240s，请求级可覆盖（assess/submit 300s、feedback 330s、report 300s） | api/index.js:16 + diagnostics.js:43 等 |
| Electron IPC 代理 | axios timeout 恒透传为 timeoutMs（无默认掐断）；直接调 window.api.http 才落 120s 默认 | api/index.js:31 / http-proxy.js:33 |
| SSE 看门狗 | 浏览器 60s 无数据断流；Electron 无看门狗无心跳 | diagnostics.js:304-310 / :361-379 |

结论：链路贯通无断裂；真正的风险在 P0-4/P0-5（事件缺失而非超时配置）。
