# 测试数据：完整输入输出示例

> 赛题 XH-202630 作品要求所对应的「测试数据」交付材料。
> 版本：v1.0 | 日期：2026/09/01

本文面向评审，演示 KMatch·知链「多智能体协同个性化学习」在**两类差异显著的画像**下，从**输入画像 → 多智能体协同中间态 → 最终学习资源**的完整输入输出走读。所有数据均取自仓库内真实文件，每个字段标注来源，**不含任何虚构字段**。

选择的两组画像差异最大化：**组 1** 为完全零基础的学生（理论 0 经验、慢节奏、需从最基础节点讲起）；**组 2** 为已有前端项目经验的开发者（理论水平更高、快节奏、进阶式解读）。二者在 `theory_level`、`time_per_week`、适配背景（`adaptation_profile`）与资源措辞上呈现明显梯度对比。

---

## ① 数据来源与脱敏声明

| 数据文件 | 说明 |
|:---|:---|
| `data/user_profiles/profile_*.json` | 10 组**人工构造的合成画像**，虚构人物（如"零基础的小王""全栈目标小陈"），不含任何真实自然人的身份信息。人口学字段（年龄段/学历/专业/经验月数）为教学适配的典型组合。 |
| `data/quality_report.json` | M5 质量检测批量跑批输出的机读报告：逐画像的 `profile`（测评后画像）、`weak_topics`、`resources`（最终学习资源）与 `independent`（独立裁判）口径。 |
| `data/workflow_runs/<session_id>/run.json` | 一次的耐久 run 记录：`request`（输入）+ `workflow`（流程定义快照）+ `orchestration_events`（多智能体协同中间态）+ `summary`。 |
| `data/workflow_runs/<session_id>/events.jsonl` | append-only 事件时间线（审计）。 |

**脱敏声明**：本测试数据全部为合成数据（虚构画像 + 领域专业知识节点 + 教学题目），**不包含任何真实个人的姓名、联系方式、邮箱、手机号或可识别的业务数据**。画像中的"年龄""学历""专业"等均为抽象的教学适配分层维度，不指向任何真实自然人。后端运行时已内置交互日志脱敏组件（`backend/app/utils/redaction.py`），开启 `PRIVACY_REDACT_INTERACTION_LOGS=1` 即对落盘的 `answers / practical_evidence / learner_key / api_key / email / phone / name` 等敏感键名打码（详见《数据合规与隐私保护说明》§交互日志脱敏规则表）。

> **注**：下述"资源内容摘录"均为**截断示例**（每条保留开头约 220 字符并标注省略），完整原文见仓库 `data/quality_report.json` 对应 `per_run[].resources[].content`。

## ④ 评审如何复现

### 4.1 一键跑批（M5 质量检测，产出 `data/quality_report.json`）

```bash
cd backend
# 依赖: Neo4j 已起 + .env 配 LLM_API_KEY (demo 模式 LLM 自动作答)
python scripts/run_quality_test.py                          # 跑全部 10 组内置画像
python scripts/run_quality_test.py --profiles beginner web_dev   # 只跑这两组
python scripts/run_quality_test.py --no-judge               # 仅自评指标(跳过独立裁判)
```

> 跑批产出：`data/quality_report.json`（机读）+ `docs/质量与验收/质量检测报告.md`（人读）。上述"组 1 / 组 2"的资源与弱项即来自该文件对应 `per_run[].{profile, resources}`。

### 4.2 API 交互复现（interactive 会话，学习体验入口）

启动后端后（`GRAPH_STORE=embedded uvicorn app.main:app --reload` 或 Neo4j 版），按接口走一次全程，即可得到与上文格式一致的 `assess → submit → 图谱/资源 → 运行历史` 数据：

| 端点 | 说明 |
|:---|:---|
| `POST /api/diagnostics/assess` | 学情测评（demo 跑全流程 / interactive 仅出题） |
| `POST /api/diagnostics/assess/stream` | SSE 流式测评（逐步推送进度） |
| `POST /api/diagnostics/submit` | 提交答题（interactive 判分 + 动态反馈 + 图谱组装；入参含 `answers`/`learning_style_quiz`/`practical_evidence`/`demographics`/`time_per_week`/`preferred_pace` 等） |
| `POST /api/diagnostics/feedback` | 动态反馈内容再生（按 advance/remediate/scaffold 针对性生成） |
| `GET /api/diagnostics/runs` | 最近 run 摘要列表 |
| `GET /api/diagnostics/runs/{session_id}` | 读取一次 run 记录（复盘/续跑，含 `orchestration_events`） |

**复现步骤（interactive）**：

1. `POST /api/diagnostics/assess`（`mode=interactive`）→ 返回 `session_id` 与题目；
2. 作答后 `POST /api/diagnostics/submit`（带 `answers`、可选 `learning_style_quiz`/`practical_evidence`/`demographics`）→ 返回 `profile`（含 `weak_topics`/`recommended_path`）、`knowledge_graph`、`orchestration_log`、`orchestration_events`；
3. `GET /api/diagnostics/runs/{session_id}` → 读取落盘的 `run.json`（`request` + `orchestration_events` + `summary`），即为本文 §② / §③ 展示的中间态结构。

### 4.3 数据镜像说明

`data/` 下的 `quality_report.json` 与 `data/workflow_runs/*/run.json` 是随仓库**已固化的示例运行数据**，评审无需联网 LLM 即可核验文中字段、弱项、资源三形态与协同事件流；如需现场重跑得到**完全一致**的数值，需按 4.1 接通 Neo4j 与 LLM 后执行（重跑结果因 LLM 抽题/作答的随机性可能略有差异，但字段结构与字段语义一致，且 `run.json` 记录了 `workflow_id` 可溯源的流程拓扑）。
